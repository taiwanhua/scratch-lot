# module-scaffold

把「新增一個固定欄位的後台 CRUD 模組」拆成兩段:**plan** 把需求問成一張規格卡,**build** 照規格卡實作。

步驟正本是 `docs/agents/module-scaffold.md`(下稱**正本**)。本 skill 只管問什麼、照什麼順序做、做到哪算完;每一步的做法打開正本對應的節,不在這裡重寫。檔案路徑與規則編號的指路清單在 [references/pointers.md](references/pointers.md)。

欄位由使用者在後台設計的**表單模組**不走本 skill:由 seed 宣告 `engine: "form"`,並在專案入口的 `forms` 清單登記,步驟見正本的「表單模組路線」。

藍本:示範模組2 是**最小可行模組**,下文的「預設」全部取自它;要選配就回示範模組1 對照(正本「示範模組 1 vs 2 差異對照表」)。

## 0. 決定模式

使用者已明示 plan/build 或指定實作 issue 時直接沿用,不重問模式;只有無法從任務判定時才詢問以下選項:

- **`plan`**:只做需求確認 → 產出規格卡(可選再產 issue 草稿)。不動任何檔案。
- **`build`**:手上已有「確認」過的規格卡(對話裡、或一張 issue),照 §3 實作。給無 session 的 agent 用。

使用者給了 issue 號就是 `build`:`gh issue view <n> --json title,body,comments` 讀出規格卡。票上沒有規格卡、或規格卡有空格,退回 §1 補問缺的那幾輪。

## 1. 需求確認四輪(plan)

規則,四輪都適用:

- **一輪一組問題**,答完才問下一輪。每輪開頭列出本輪的題目與預設值。
- **有預設值的題直接列出預設**;使用者不改就採用,並在規格卡記進「採用預設的」。
- **沒有預設值的題必須有答案**。二選一沒答的**再問一次**,不替使用者選;答案與前面衝突時,指出衝突、請使用者裁決。
- 使用者的答案會牽動後面的題(例:有欄位級權限 → 第 4 輪多兩筆權限),在後面那一輪直接帶出來,不要漏。
- 本輪的完成判準:表內每一題都有「使用者答的」或「採用預設」其中之一。

### 第 1 輪:模組身分

| 題目                         | 預設                                                                | 備註(答題時告訴使用者)                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 模組 key                     | 無(必答)                                                            | 累加父 key:`<父key>.<自己那段>`,段用 kebab-case                                                                                    |
| 模組名稱(側欄與頁籤顯示)     | 無(必答)                                                            | 詳情 / 編輯頁的頁籤自動顯示成「模組名 — 檢視・項目名」/「模組名 — 編輯・項目名」,項目名取 `name` 欄                                |
| 父模組                       | 無(必答)                                                            | 可答「頂層」;父不存在時追問要不要新建一個 `group` 節點(它的 key / 名稱 / 順序 / 圖示)                                              |
| 生成哪些頁                   | 四頁:列表(`link`)+ 詳情 / 新增 / 編輯(`hidden`,key 以 `-page` 結尾) | 少一頁 = 少一個模組 key,也少一個入口(沒綁詳情頁,列上就沒有「檢視」)                                                                |
| 列表頁的側欄類型             | `link`                                                              |                                                                                                                                    |
| 同層順序 `order`             | 同一個父底下、非 `hidden` 節點的最大值 + 1(沒有同層就 1)            | 查 `apps/db-migrator/seeds/base/modules/` 與 `seeds/project/registry.ts` 的模組來源;頂層有個 `hidden` 的 `api` 節點(order 99),不算 |
| 是否根組織專屬(`isRootOnly`) | 否                                                                  | 是 = 租戶看不到、租戶管理員模板扣除                                                                                                |
| 圖示                         | 不宣告(側欄預設圖示)                                                | 只能從白名單 `packages/domain/src/module-icon/keys.ts` 選;這是初始 seed 值,之後由人在頁面上改                                      |

### 第 2 輪:資料

| 題目                  | 預設                                                               | 備註                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 實體名 / collection   | 無(必答);先提一個由 key 推出的 snake_case 複數名給使用者確認       | 例:`recipe.tag` → `recipe_tags`                                                                                                                          |
| 欄位清單              | 示範模組2 的三欄:`name`(字串、必填)、`note`(多行、選填)、`enabled` | 每欄逐一答:key / 型別 / 必填 / 唯一 / enum 選項 / 預設值。`name` 與 `enabled` 是共用頁面的最低要求                                                       |
| 唯一欄位的範圍        | 無唯一欄                                                           | 有唯一欄就必答範圍:同組織內 / 全域。兩支示範模組都沒有唯一欄,違反時沿用 `VALIDATION_FAILED`(GQL-04 不新增 code);把「藍本無先例」記進規格卡的「待人處理」 |
| 欄位級權限            | 無                                                                 | 有 = 該欄多 `<key>.show-<欄位>` / `<key>.edit-<欄位>` 兩筆權限,正本「欄位級權限欄的四件事」全做                                                          |
| 狀態欄(enum `status`) | 無                                                                 | 有就列選項的 value 與顯示名                                                                                                                              |
| 上傳欄                | 無                                                                 | 每一欄必答:公開或私有(預設私有;要 CDN / SEO / 未登入展示 / 社群分享才公開,ADR-0010)、檔型、大小上限                                                      |
| 變更歷程              | 無                                                                 | 有 = 編輯頁多一筆頁面自有權限 `<key>.edit-page.show-history`                                                                                             |
| 示範 / 初始資料       | 無                                                                 | 有就列筆數與內容(正本「1b 示範 / 初始資料」)                                                                                                             |

非字串欄位(數字、日期、enum、參照)在表單上都是 `custom` 欄位,要自己寫 `render`;把這點告訴使用者,讓他知道欄位型別的成本。

### 第 3 輪:功能

| 題目            | 預設                                  | 備註                                                                                                          |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 搜尋欄          | 有,比對 `name` 與 `note`              | 受欄位級權限保護的欄位不進搜尋                                                                                |
| 下拉篩選        | 無                                    | 有就必答選項來源:固定 enum / 欄位管理的選項 / 別的模組。來自別的模組時,沒有該模組權限的人看不到篩選、該欄唯讀 |
| 每頁筆數        | 10                                    | api 上限 100                                                                                                  |
| 詳情頁欄位      | 欄位清單全部,依清單順序               |                                                                                                               |
| 填寫提示區塊    | 無                                    | 有 = 新增頁多一筆頁面自有權限 `<key>.create-page.show-tips`                                                   |
| 啟用 / 停用切換 | 有(列表的開關,守 `<key>.edit`,不自鎖) | 沒有就列表的「啟用」欄維持唯讀標籤                                                                            |

### 第 4 輪:權限與範圍

先把前三輪帶出的權限列成一張表給使用者看,再問下表。

| 題目                   | 預設                                                     | 備註                                                                                                  |
| ---------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 個別權限               | `view` / `create` / `edit` / `delete` 四筆,全綁列表頁    | wildcard `<key>.*` 每個節點自動一筆,不列                                                              |
| 頁面自有權限           | 前兩輪帶出的那幾筆(沒有就無)                             | 綁在按鈕 / 區塊所在的那一頁(ADR-0004)                                                                 |
| 資料範圍目標           | 不宣告(查詢只受可見範圍保底)                             | 宣告就必答:哪些**業務欄位**可進規則;enum 欄列固定選項,value 與 schema 一致(ADR-0008)                  |
| 租戶管理員模板         | 由第 1 輪推出:非根組織專屬 = 自動納入模板,沒有另外的開關 | 告訴使用者:**既有租戶**的租戶管理員副本不會自動拿到(ADR-0009),要補由人在角色管理頁授予                |
| help.md 要特別講的規則 | 照說明檔骨架三節(做什麼 / 常用操作 / 重要規則)           | 提醒使用者:讀者是租戶使用者,不出現根組織 / 租戶 / 開通 / 跨租戶 / 平台這類詞;聯絡窗口寫「系統管理員」 |

## 2. 規格卡(plan 的產出)

四輪答完,輸出一張 Markdown 規格卡,格式固定:

```markdown
## 規格卡:<模組名>(`<模組 key>`)

| 項目 | 使用者明確選的 | 採用預設的 |
| ---- | -------------- | ---------- |
| …    | …              | …          |

### 模組樹

| key | 名稱 | sidebarType | 父 | order | 路由段 |

### 欄位

| key | 型別 | 必填 | 唯一 | enum / 預設值 | 欄位級權限 |

### 權限表

| 權限 key | 綁哪一頁 | 它是哪一頁的什麼 |

### 選配(對照正本「示範模組 1 vs 2 差異對照表」逐列標做 / 不做)

### 要畫的畫面(Figma,本 skill 不畫)

### 待人處理

<既有租戶補授權、要另開文件票的規則疑點…;沒有寫「無」>
```

- 「項目」列出四輪的每一題,答案放在兩欄之一,另一欄寫「—」。
- 卡片最後一行寫:「回覆『確認』定案;要改哪一項直接說。」
- **關卡**:使用者回「確認」才算定案。改了任何一項就重出整張卡、再等一次「確認」。
- 完成判準:使用者回了「確認」,且卡上沒有空格。

### issue 草稿(可選)

定案後問一次:「要順手產成 GitHub issue 嗎?」要的話:

1. 用 Write 把內文寫到 scratchpad 的 `module-scaffold-<模組key>.md`,三節照 issue-tracker 的票面:
   - `## What to build`:一句話說模組做什麼 + 整張規格卡 + 「照 `/module-scaffold` 的 `build` 模式實作」。
   - `## Acceptance criteria`:核取清單,每項寫成可驗的一句(照 §3 的整體完成判準展開,加上規格卡裡每項選配各一條)。
   - `## Blocked by`:依賴的票號;沒有寫「無」。
2. 草稿先貼給使用者看;使用者說開才執行 `gh issue create --title "<模組名>模組:<一句話>" --body-file <檔>`,回報 issue 連結。

`plan` 模式到此結束,不進 §3。

## 3. build:照規格卡實作

先讀 `CLAUDE.md`,再依 `docs/agents/issue-tracker.md`「實作一張票」認領、建立工作樹與交付。建置、單檔測試及全套驗證命令只依 `docs/agents/toolbox.md`,不在本 skill 另存指令副本。

逐步執行正本 `docs/agents/module-scaffold.md` 的步驟 0–8,對照規格卡驗收:模組文件、seed、schema/repository、API、documents、後台頁面、help、測試及文件回寫。專案功能新增放 project 來源並經固定入口組裝,共用接縫與替換規則見 `docs/standards/general/structure.md` STRUCT-12、`docs/concepts/frontend-architecture.md` 與 `docs/concepts/data-layer-and-isolation.md`;不能把專案登記寫回底座來源或以 spread 蓋掉原版。

完成判準以正本「交件前檢查清單」與票面驗收為準,全部確認後依 issue-tracker 開 PR。PR 附測試結果、mock 畫面與規則回饋;E2E 僅列建議與理由,由使用者決定是否觸發。部署由主流程依既有 release SOP 處理。

## 4. 不做的事

- **二選一由使用者裁決**:缺答案就問,在規格卡或 PR 裡寫明誰選的。
- **規則本文只回報**:ADR、`docs/standards/`、底座 `CONTEXT.md`、`docs/agents/module-scaffold.md` 寫錯或缺漏,寫進 PR 的「規則回饋」,由文件票改。模組文件、help.md 與 `CONTEXT-PROJECT.md` 的專案新詞是本模組自己的,照 §3 寫。
- **Figma 只列清單**:要畫的畫面寫在規格卡「要畫的畫面」,本 skill 不開 Figma。
- **共用元件保持原樣**:`components/base/crud/` 需要改才做得出來時,停下回報,另開票。
