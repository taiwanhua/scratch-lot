# scratch-lot-onboarding

開通清單正本是 `docs/modules/project/lottery-onboarding.md`(下稱**正本**)。本 skill 只管問什麼、照什麼順序做;每一步做什麼、為什麼、在哪個畫面、自動還是人工,一律以正本為準,不在這裡重寫。兩者不一致時以正本為準並回報差異。

**密碼不經手**:不問、不收、不寫任何密碼(租戶管理員的、員工的都不要)。使用者若在對話裡貼了密碼,請他改掉那個密碼。開通腳本的密碼只在使用者自己的終端機輸入。

## 1. 讀與確認前提

1. 讀正本全文(開通步驟、執行開通腳本、角色配方、表單代號與流程)。
2. 確認:平台管理員已在組織管理「開通租戶」建好租戶與首任租戶管理員,那位管理員已用啟用信設好密碼;知道要開通的環境(dev / staging / production)。缺了就停下,請使用者先完成。

## 2. 問新租戶的資料

只問正本「執行開通腳本」的開通資料需要的,已經給過的不重問:

- 租戶短碼(平台管理員開通租戶時填的)
- 分店名稱(一家一列)
- 總部是不是某家分店(是的話是哪一家)
- 使用者:姓名、信箱(帳號預設同信箱,可另給)、所屬分店、是不是總部人員、角色(總部管理 / 店長 / 店員)
- 崗位:這個機構有哪些崗位(專案不內建崗位;收銀點與人力需求範本用到的崗位都要列;顏色選填)
- 正本「開通步驟」表裡標「自動(資料由操作者提供)」的其他項目(之後的模組上線後會變多;照正本當下的表問)

## 3. 寫開通資料檔

照正本的 JSON 形狀寫一個檔,放在 repo **外面**(例:使用者的暫存資料夾),檔名帶租戶名稱;不放密碼(有 password 欄位的檔會被腳本拒絕),不 commit。寫完把內容摘要給使用者核對。

## 4. 請使用者在自己的終端機執行

給使用者完整的一行指令(正本「執行開通腳本」),`--api-url` 填該環境的 api 網址(`deploy/project/cloud.json` 的 `apiUrl`)、`--tenant` 填租戶短碼(開通租戶時填的)、`--account` 填首任租戶管理員帳號、`--plan` 填上一步的檔案路徑。說明:

- 會提示輸入租戶管理員密碼,輸入時不顯示
- 每一步印「✓」或「✗」;停在某一步時照錯誤補好(多半是權限),再跑同一行指令,會從缺的開始補
- 新建的使用者會收到啟用信,自己設定密碼

請使用者把輸出貼回來(輸出不含密碼),逐步對照正本確認做完了哪些。**不要自己替使用者執行這行指令**。

## 5. 列人工步驟

依正本「開通步驟」表,把「開通腳本」欄不是「自動」的項目列成勾選清單給使用者(含畫面位置),至少包括:收據機與印表機(有才做)、經銷商的兩個批購基準日、排班規則與人力需求範本確認、通知收件人與提醒時間確認,以及正本當下仍標人工的收銀點、乙類、銀行帳戶、流程。

## 6. 回報

列出:開通資料檔的位置(提醒使用者用完可刪)、腳本做完的步驟、還沒完成的人工步驟。
