只在手動觸發時跑(TEST-05)。選劇本的字串用前綴「scratch-lot 劇本」:

| 情境         | Bash                                                              | PowerShell                                     |
| ------------ | ----------------------------------------------------------------- | ---------------------------------------------- |
| 只跑專案劇本 | `E2E_GREP="scratch-lot 劇本" pnpm e2e`                            | `$env:E2E_GREP="scratch-lot 劇本"; pnpm e2e`   |

| CI           | `gh workflow run e2e.yml --ref <分支> -f grep="scratch-lot 劇本"` | 同左                                           |

## 共同前置

前置全部走 api(`apps/e2e/src/fixtures/project/`)。harness 的 `update` 會跑專案種子,所以模組、權限與受管表單都在,不必改 harness。

刮刮樂的張只有一條路進系統:進貨單點收。每條劇本照下列順序鋪資料:

1. 平台管理員把受管表單分派給租戶:進貨單、結帳確認、盤點確認(受管表單不會隨開通自動分派)。
2. +tenant 建崗位、遊戲(單價 200 元,一本 10 張)、甲類、銀行帳戶。
3. 三張表單各綁一關流程,審核者 = +tenant。盤點確認設「申請人是審核者時自動通過」,送出即完成;其餘照常審核。結帳確認沒綁流程時,送出後檢視頁沒有結帳單(實測),所以一定要綁。
4. 分店設定盤點制度,再建 A 台、B 台,送進貨單、點收一本,拆本:#001–#006 到 A 台、#007–#010 到 B 台。
5. +tenant 開 A 台的班,期初零用金 0,應有現金就是賣的錢。

其他前提:

- **帳號**:全部用 +tenant(租戶擁有者),劇本不驗權限。
- **掃描**:`scanWithGun` 在頁面發 keydown,走真的 `useScanner` 分派(`injectScan` 只在 bundle 內)。手輸的步驟直接填輸入框。
- **即時信號**:E2E 不起 `apps/realtime`,看板頂部一直是「重新連線中」。畫面要靠自己的請求重抓,不能靠 `board` 信號;別人的操作要重新進頁才看得到。

## scratch-lot 劇本 1 — 依張數賣、刷到實體對號、刷退的票

- **用哪一頁**:店面管理看板
- **帳號**:+tenant,本機收銀點 = A 台
- **前置**:張數店(分店自訂)
- **E2E**:`scenario-01-count-sale-return.spec.ts`

1. 按 [依張數標記售出],賣 2 張。
2. 看板刷條碼賣 #001(系統帶入的已售·未對號)。
3. 看板刷未售的 #004。
4. 打開 [最近售出],條碼槍刷未售的 #005 → 撤銷確認 → 按 [撤銷]。
5. 在「刷退的票」手輸 #004 → 撤銷確認 → 按 [撤銷]。

**預期**:

- 步驟 1:提示「遊戲 × 2 張,合計 400」;本班已售 2 張 / 400;#001、#002 已售·未對號。
- 步驟 2:售出提示帶「已對號」;本班已售 3 張;#001 確定已售,#003 接手已售·未對號。
- 步驟 3:看板刷未售的票就是賣出,本班已售 4 張。
- 步驟 4:[最近售出] 開著時刷未售的票是退票,按 [撤銷] 前 #005 沒有被賣出。撤銷後提示「已撤銷。已對號:這張接手了 hh:mm 依張數售出的 1 張」,本班已售 3 張,#005 未售。
- 步驟 5:刷條碼賣出的票照張號撤,本班已售 2 張,已售·未對號的張數不變。

## scratch-lot 劇本 2 — 交班張數盤點

- **用哪一頁**:交班結帳精靈
- **帳號**:+tenant,本機收銀點 = A 台
- **前置**:張數店;這一班刷條碼賣了 #001,A 台剩 5 張
- **E2E**:`scenario-02-checkout-count-stocktake.spec.ts`

1. 按 [交班結帳],看第 ① 步的選項。
2. 「實際剩幾張」填 3,按 [確定],再按 [盤完,前往差異核對]。
3. 按 [算售出]。
4. 第 ② 步略過;第 ③ 步填實點 600(500 × 1、100 × 1)。
5. 第 ④ 步送出,回看板。

**預期**:

- 步驟 1:預設「現在盤點」,沒有「跳過盤點」(+tenant 有 `store.skip-stocktake` 也一樣)。
- 步驟 2:按 [確定] 後才顯示「系統 5 · 實際 3 · 少 2 張」。
- 步驟 3:差異處理完之前 [下一步] 停用。[算售出] 立即生效,#002、#003 記已售·未對號,算進這一班。
- 步驟 4:應有現金列「銷售(3 張)」,合計 600。[算售出] 的 2 張要馬上算進來,不等 `board` 信號。
- 步驟 5:檢視頁的結帳單是銷售(3 張)+ 600;A 台回到未開班。

## scratch-lot 劇本 3 — 全店重刷

- **用哪一頁**:店面管理看板、全店重刷頁、庫存管理的待查·遺失分頁
- **帳號**:+tenant,本機收銀點 = A 台
- **前置**:張數店;A 台臨時盤點少 1 張記 [待查](api 送盤點確認),系統帶入 #001。情境是 #001 其實還在,不見的是 #002
- **E2E**:`scenario-03-rescan.spec.ts`

1. 看板按重刷提醒的 [全店重刷 遊戲 X],確認位置,開始。
2. 回看板看移櫃,再硬送一次 `moveLotteryTicketsByCount`。
3. A 台條碼槍刷 #001、#003–#006(不刷 #002),按 [這裡刷完了]。
4. B 台手輸 #007–#009(不刷 #010),按 [這裡刷完了]。
5. 庫存直接按 [這裡刷完了]。
6. 打開待查·遺失分頁。
7. 回看板展開卡片。

**預期**:

- 步驟 1:確認視窗列「A 台、B 台、庫存(3 個)」。
- 步驟 2:橫幅「遊戲 X 全店重刷中,暫停移櫃 · 已刷 0/3」;展開卡片的 [刷條碼移櫃]、[依張數移櫃] 變灰並寫原因;硬送回 `MOVE_PAUSED`。
- 步驟 3:#001 標「已對號」,和沒刷到的 #002 互換,待查·未對號變成 #002。
- 步驟 5:「全店重刷完成 · 3/3 個位置」與結果摘要。
- 步驟 6:#002(未對號清掉)與 #010(B 台沒刷到)都是確定待查,列出張號,不標「系統預設帶入」。
- 步驟 7:提醒與橫幅消失,[依張數移櫃] 恢復可按。

## scratch-lot 劇本 4 — 新開分店跟著上層預設、切換回編號與取消

- **用哪一頁**:店面管理看板、刮刮樂設定
- **帳號**:+tenant,本機收銀點 = A 台
- **前置**:租戶預設先改成張數盤點,之後才開「新開分店」,這家店沒有 `lottery_store_count_modes` 那一筆
- **E2E**:`scenario-04-count-mode-switch.spec.ts`

1. 看板按 [依張數標記售出] 賣 1 張。
2. 打開刮刮樂設定,選這家店,看盤點制度那一列。
3. 按 [自訂],選編號盤點,看後果說明,儲存。
4. 回看板。
5. 回設定按 [取消轉換],確認。
6. 回看板。

**預期**:

- 步驟 1:新分店沒有那一筆也是張數店,[依張數標記售出] 可用。
- 步驟 2:值「張數盤點」,來源「沿用:…」。
- 步驟 3:還有未對號的張,對話框寫「新開分店會進入轉換中」;存檔後值變成「張數盤點 → 編號盤點(轉換中,等補點編號)」。
- 步驟 4:頂部「轉換中:請完成補點編號」與 [補點編號];[依張數標記售出] 不顯示,[最近售出] 照常。
- 步驟 5:值回到張數盤點,來源「本店自訂」。
- 步驟 6:[依張數標記售出] 回來,轉換中提示消失。

沒有未對號時直接改成編號,由 api 測試覆蓋(`apps/api/src/project/lottery/settings/lottery-settings.test.ts`);補點編號核准後改成編號見劇本 5。

## scratch-lot 劇本 5 — 補點編號核准變回編號店、營運報表

- **用哪一頁**:輸出報表(營運報表、日報、那家店)、店面管理看板、補點編號的盤點頁、刮刮樂設定
- **帳號**:+tenant,本機收銀點 = A 台
- **前置**:張數店;盤點確認改成「照常審核」(要另外核准)。api 依張數賣 2 張(系統帶入 #001、#002);A 台臨時盤點剩 3 張、少 1 張記 [待查](系統帶入 #003),核准。情境是 #001–#003 其實都還在,不見的是 #004–#006。之後 api 把這家店改回編號盤點,進入轉換中(設定頁的畫面在劇本 4)
- **E2E**:`scenario-05-renumber-report.spec.ts`

1. 營運報表日報 [預覽],切到這家店的工作表。
2. 看板轉換中提示的 [補點編號] → 補點編號的盤點頁。
3. A 台點 #001–#003(虛線)、B 台點 #007–#010,[差異核對 →]。
4. [送出 →] → [送出盤點確認申請];api 核准(劇本不驗審核畫面)。
5. 回看板。
6. 刮刮樂設定 → 盤點制度那一列 [變更紀錄]。
7. 營運報表日報再 [預覽] 一次。

**預期**:

- 步驟 1:第二列「含估算」;1 銷售有「依張數標記售出」2 張;4 庫存異動有「對號成本調整」,核對「對得上」。
- 步驟 2:標題「補點編號 · 全店」,圖例「虛線 = 系統預設帶入的張號」。
- 步驟 3:「自動對號 3 張(不算差異)」:#001–#003 和 #004–#006 互換。
- 步驟 4:核准後沒有未對號的張;#004、#005 已售,#006 待查。
- 步驟 5:變回編號店:卡片「剩 N / M」沒有「約」,沒有遊戲合計「剩 N 張 · M 本」,沒有轉換中提示。
- 步驟 6:有一筆「轉換中 → 編號(補點編號核准)」(`renumber_approved`)。
- 步驟 7:補點編號核准晚於這一期最後一筆未對號事件,所以**不再含估算**(`docs/modules/project/reports.md`「張數店」的估算判定);「對號成本調整」列還在,核對「對得上」。
