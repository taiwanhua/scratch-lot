# 專案規格:刮刮樂 + 排班與出勤

> 狀態:草稿,待使用者審閱。實作在刮刮樂專案 repo `C:\project\scratch-lot`(底座與專案都在這裡做)。底座機制(B1 至 B18、第 19 至 26 項、人員條件)的設計與實作見 `docs/tmp/spec-base-round.md`(以下稱「底座規格」);本文件只寫**本專案怎麼設定與使用**。
> 原則:一個東西只有一個名詞;金額一律正數、由類型表示方向;紀錄只新增、更正用反向紀錄;一個使用者動作 = 一個 Mongo 交易(底座 B13),寄信 / 通知 / 信號 / 列印在交易成功後執行。

## 0. 範圍與模組歸屬

> **S2 測試案例**(見底座規格 0.3a):底座的 B10 全域掃描監聽、欄位選項顏色、B11 報表登記,這一輪**先在本專案階段以專案客製實作**(`project/` 路徑、客製替換、專案 seed),回收前再升格到底座。本文件引用它們的地方照常寫,實作位置以底座規格 0.3a 為準。

| 模組       | 歸屬               | 說明                                                                     |
| ---------- | ------------------ | ------------------------------------------------------------------------ |
| 刮刮樂     | 專案模組           | 本文件第 1~13 章                                                         |
| 排班與出勤 | **獨立的專案模組** | 本文件第 14 章;不引用刮刮樂的任何資料表,將來可給其他行業使用或回收到底座 |

- **依賴方向:刮刮樂 → 排班**。刮刮樂呼叫排班提供的查詢(「某人在某店某時間的排班」);排班不知道刮刮樂存在。排班表上顯示收銀點名稱,是刮刮樂以登記方式提供給排班畫面的。
- 每個專案 repo = 底座 + 一個專案。本專案的 lookup 來源 key、資料表一律加前綴:刮刮樂 `lottery_`、排班 `schedule_`。

## 5. 主檔

### 5.1 遊戲 `lottery_games`(檔案管理 → 遊戲)

| key                                         | 名稱                         | 型別                   | 必填 | 規則                                                                                 |
| ------------------------------------------- | ---------------------------- | ---------------------- | ---- | ------------------------------------------------------------------------------------ |
| gameCode                                    | 遊戲代號                     | 字串 4 碼              | ✅   | `^\d{4}$`;租戶內唯一;有庫存後鎖定                                                    |
| name                                        | 遊戲名稱                     | 文字 30                | ✅   |                                                                                      |
| unitPrice                                   | 單張金額                     | 正整數                 | ✅   | 可輸入的下拉:100 / 200 / 300 / 500 / 1,000 / 2,000,也可自填;有庫存後鎖定             |
| ticketsPerBook                              | 整本張數                     | 整數 1~999             | ✅   | 選預設面額自動帶入 100 / 100 / 100 / 50 / 25 / 18,可改;非標準組合只提示;有庫存後鎖定 |
| bookPrice                                   | 整本金額                     | 整數                   | —    | 單張金額 × 張數,API 計算後存                                                         |
| defaultRate                                 | 預設批購金額率               | 整數 0~100             | ✅   | 不收小數;成本有小數時四捨五入                                                        |
| color                                       | 顏色                         | 色票代號               |      | 從底座 `tagPalettes` 選;看板卡片使用                                                 |
| status                                      | 狀態                         | on_sale / discontinued | ✅   | 預設販售中                                                                           |
| launchedAt / discontinuedAt / claimDeadline | 上市日 / 停售日 / 兌獎截止日 | 日期                   |      |                                                                                      |
| note                                        | 備註                         | 文字 1000              |      |                                                                                      |

- 面額與張數的對照表是程式常數,只有一份。張號從 001 起,標準最後一張 = 張數;瑕疵跳號記在本上。
- 停售:不能出現在新的叫貨單與進貨單;調貨、銷售、盤點照常。
- 刪除:只有**從來沒有被任何本、叫貨單、進貨單引用**才能刪除(`games.delete`),否則只能停售。
- 新增、編輯、詳情都是頁面,支援手機(單欄、儲存列固定在底部、錯誤時自動展開並捲動)。
- 列表欄位:代號、名稱、面額、張數、整本金額、預設批購金額率、狀態、上市日;篩選:狀態、面額、關鍵字。

## 6. 店面管理 `store`

### 6.1 頁面

- 分店選擇器(預設目前組織,網址參數)、本機收銀點、連線狀態小圓點(綠 = 即時;黃 = 重新連線中、每 60 秒更新);**沒有重新整理按鈕**。
- 頂部顯示「上次日結:10/13(已 3 天)」、[盤點](臨時盤點,第 6.8 節)、[存銀行](第 6.11 節)與 [日結](第 6.10 節)。
- 分頁:看板 | 班次結帳歷史紀錄(結帳確認申請的列表)| 盤點紀錄(盤點確認申請)| 撤銷售出 | 現金更正 | 其他申請(租戶自己綁到本模組的表單,用引擎預設列表)。
- 多台裝置同步:底座 B6 頻道 `board:<分店>`,刷票信號每 2 秒合併一次。

### 6.2 看板

- 版面:每個收銀點一條**收銀點標題列**,下面是這個收銀點檯面上各本的卡片;收銀點依排序由上到下。
- 收銀點標題列:名稱、狀態(未開班 / 開班中)、負責人、應有現金;按鈕依狀態與權限顯示(沒有權限不顯示):未開班 → [開班];開班中 → [兌獎] [投庫] [出庫] [拆本] [交班結帳]。
- [開班] 開彈窗:期初零用金(帶入,唯讀,顯示來源:出庫單或上一班「留給下一班」)、系統找到的排班(可改選,第 14.9 節)、崗位不一致的提醒。
- 卡片 = 某本 × 某收銀點的檯面:遊戲名稱(遊戲顏色)、面額、本號、剩餘 / 總張數、今日售出;待標註、號碼不明、剩很少的提示。
- 統計列**只顯示本班**的售出張數與金額。
- 距離上次盤點超過 24 小時,頂部提醒「建議盤點一次」。

### 6.3 銷售、快速銷售、當下撤銷

- 刷條碼:底座 B10 全域掃描監聽。看板頁用途 = 銷售;其他沒有宣告用途的頁面刷到票 → **快速銷售**小視窗(Enter 確認、Esc 取消)。
- 輸入方式:條碼槍、相機、背面編號 `5164-1-056527-099-0-6`、正面編號 `056527-099` / `056527099`、正面條碼 `0056527099`。
- 銷售條件:裝置設定了本機收銀點、該收銀點有開著的班、使用者有 `store.sell`;不符合只顯示票的資訊。
- **錢算在賣票的那一班**(本機收銀點)。票在別的收銀點檯面 → 提示「這張票在店外攤位,確定在店內櫃台售出?」→ 確認後寫「移櫃」+「售出」。
- 刷到時:本號在本店對到兩款以上遊戲 → 選遊戲;不是本店的票、已售、瑕疵、報廢、被單據鎖定 → 擋下;未拆的本 → 詢問是否拆本並售出;待查或遺失 → 提示尋回(`inventory.recover`,原因必填,回到刷到的那家店的庫存)。
- 手動標記:點格子選多張,一次確認。
- **當下撤銷**(`store.undo-sale`):自己賣的、30 分鐘內、這一班還開著、那張票之後沒有其他異動 → 寫「撤銷」事件,應有現金減少。超過就送撤銷售出申請。

### 6.4 拆本、收回、移櫃

- 拆本:選擇放到哪個收銀點(預設本機收銀點);同一本可以分放不同收銀點;拆本時在本的頁面標註瑕疵張號(`inventory.void-tickets`)。
- 收回(檯面 → 庫存)、移櫃(收銀點之間):寫事件,不需要審核。

### 6.9 結帳精靈(交班)與 `lottery_checkouts`

**交班精靈**:① 盤點(沿用 30 分鐘內 / 現在盤點 / 跳過:`store.skip-stocktake`,原因必填,報表永久標示「未盤點」)→ ② 兌獎(逐筆,可補登)→ ③ 抽屜 → ④ 確認 → 送出結帳確認申請,列印結帳單。

```
應有現金 = 期初 + 銷售 − 兌獎 − 投庫 + 出庫 − 調貨支出(現金)+ 調貨收入(現金)− 退貨退款 ± 現金更正
          (逐項列出,每筆可點回單據;只算已完成的單據)
差額 = 實點(依面額清點)− 應有;不為 0 時原因必填(欄位管理「結帳差額原因」)
⚠ 審核中:現金更正 #C-012 +500 / 撤銷售出 #R-008 −500 → 自動帶入差額原因
留給下一班 [金額]  接班人 [使用者](選填)
```

- 接班人選填:「留給下一班」大於 0 時接班人必填;沒有接班人時「留給下一班」必須是 0(錢先投庫),結帳確認申請改由店長審核(第 8.7 節)。

**日結精靈**(第 6.10 節)。

**`lottery_checkouts` 欄位**:orgId、type(交班 / 日結)、cashPointId 與 shiftId(交班才有)、coveredFrom、coveredTo(日結的涵蓋計算期間)、stocktakeId 或 skipReason、應有現金每一項明細、實點(各面額張數)、差額與原因、審核中單據的快照、留給下一班、接班人、小金庫(應有 / 實點 / 差額,日結才有)、存入銀行(金額、帳戶,日結才有)、submissionId。

### 6.10 日結

- 入口:頂部 [日結];**這家店所有收銀點的班都已送出交班結帳**才能按;停用時滑過顯示還沒送出的班。
- **涵蓋計算期間 = 上一次日結送出 ~ 這次日結送出**;期間內送出交班結帳的班由這張日結涵蓋計算。畫面標示「涵蓋計算期間 10/14 09:02 ~ 現在(10/14、10/15 沒有日結)」。**不能補日結**;每一班只會被一張日結涵蓋計算。
- 不屬於任何一班,不會結束任何人的班;送出後再開的班算到下一次日結。
- **涵蓋計算的交班結帳必須全部核准,才能送出日結**(後端送出時再檢查一次)。
- 精靈:
  - ① **各班結帳**:表格列出涵蓋計算的每一班:收銀點、交班人、送出時間、應有、實點、差額、審核者、狀態(已核准 / 待審核 / 已退回待更正)。審核者是自己的列有 [審核],在側邊打開結帳單直接核准或退回,不離開精靈;審核者是別人的列顯示「等某某核准」;退回的列顯示「待某某更正」。狀態透過頻道 `board:<分店>` 即時更新。全部核准後 [下一步] 才能按,否則顯示「還有 N 班沒核准」。
  - ② 全店盤點(現在 / 沿用 30 分鐘內的全店盤點 / 跳過:`store.skip-stocktake`,原因必填,報表永久標示「未盤點」)。
  - ③ 小金庫(期初 + 投庫 − 出庫 ± 調貨 ± 現金更正 − 存銀行 = 應有;依面額清點、差額、原因)。
  - ④ 存入銀行(金額、帳戶,依使用組織篩選)。
  - ⑤ 確認 → 送出結帳確認申請(類型 = 日結)→ 列印日結單。
- 平常也可以在「班次結帳歷史紀錄」分頁用「待審核」篩選。
- 有已送出交班結帳的班還沒被日結涵蓋計算,而且已經過了隔天早上 → 負責人提醒「日結逾期」(第 3.4 節)、側欄計數。

### 6.11 存銀行

- 入口:頂部 [存銀行],和 [日結] 並列;權限 `store.bank-deposit`(預設只給店長)。店長覺得小金庫的錢太多時,隨時可以存。
- 填寫:金額、存入帳戶(`lottery_bank_account`,使用組織包含這家分店、使用中;只有一個時自動帶入)、備註。
- 同一個交易寫:現金流水「存銀行」(小金庫 → 銀行)+ 銀行「存入」(歸屬分店 = 這家店);列印 58mm 存款單。
- 金額超過小金庫目前的應有金額 → 擋下;實際的錢比系統多時,先用現金更正單補登。
- 不用審核,做完就生效(同投庫、出庫)。
- 記錯:到帳戶管理沖正那筆「存入」,現金流水自動產生反向紀錄。
- 日結第 ④ 步的存入銀行保留,兩邊寫的是同一種紀錄;即時現金帳與報表都列出。

| 送出後             | 自動記「批貨支出」與(有兌獎剩餘時)「兌獎入帳」(見合計;扣款帳戶、交易時間 = 送出時間、摘要寫批購日、歸屬分店 = 進貨分店);甲類兩個批購日 max 更新;叫貨單 → 已進貨 |
| 重新送出           | 不自動調整;結算區塊顯示待付 / 待退                                                                                                                              |
| 點收一本(非掛接點) | 寫 `lottery_purchase_receipts`(唯一 `(submissionId, rowId)`)、本、張(庫存)、「進貨」事件;單據須在審核中;刷到的最後張號和單上不同 → 擋下「請退回更正」           |
| 核准前             | 還有沒點收的列 → 擋下                                                                                                                                           |
| 完成時             | 不寫帳,不檢查是否結清                                                                                                                                           |
| 駁回前 / 刪除前    | 已有點收 → 擋下;駁回前另要求淨額 = 0                                                                                                                            |
| 作廢前             | 任何一張已售、已調出或已拆本 → 擋下;淨額 = 0                                                                                                                    |
| 駁回後 / 作廢後    | 甲類日期重新計算;作廢另寫「進貨作廢」事件、叫貨單回到待購買                                                                                                     |
| 撤回、退回         | 不擋                                                                                                                                                            |

**錯誤情境**:打錯 → 退回修改沒點收的列;少一本 → 保持審核中,或退回後刪除那一列(差額由結算處理);單上是 B 店、實體送到 A 店 → A 店刷到時只能選 [不入庫,轉送 B 店] 或 [通知總部更正](底座 B7 通知這張進貨單的建立者),不能直接入庫。

**列表欄位**:單號、進貨分店、甲類、批購日、扣款金額、點收進度(8/10)、結算(待退 2,000)、狀態。**列印**:進貨點收單。

### 8.3 進貨點收 `lottery_purchase_receipts`

`{submissionId, rowId, bookId, receivedBy, receivedAt, orgId}`;唯一 `(submissionId, rowId)`。

### 8.4 調貨單 `purchasing.transfer`

**單頭**:出貨分店、收貨分店(不能相同)、叫貨單(選填,收貨分店、待購買)、備註。

**明細**:遊戲、本(B2d 篩選 `lottery_book`:在出貨店、未被鎖定)、方式(整本 / 選張;只有拆過的本能選張,需要 `partial-tickets`)、張號(區段)、張數、金額(整本 = 整本金額;零碎 = 面額 × 張數)、批購金額率(預設這一本的成本率,可逐本或整組改)、批購金額。合計:調貨金額 = 批購金額合計。

**頁面**:替換新增頁(張數格子 + 刷條碼加入選取);替換檢視頁 = 第一關出貨確認清單;第二關點收(與進貨單共用元件)+ 結算區塊。

**流程**:兩關。第一關 店長限定「出貨分店」,跳過條件 `ctx.user.orgId == 出貨分店`;第二關 店長限定「收貨分店」。收貨店不發起調貨單,缺貨一律開叫貨單。

| 時機                 | 做什麼                                                                              |
| -------------------- | ----------------------------------------------------------------------------------- |
| 送出前               | 本和張都在出貨店,且不在其他未結束的調貨單上                                         |
| 送出後               | 鎖定(lockedBy)= 調貨中,不能賣;叫貨單 → 已調貨                                       |
| 第一關通過後(含跳過) | 位置改「在途」、寫「調出」事件;列印調貨出貨單;負責人提醒「調貨出貨通知」(第 3.4 節) |
| 點收一本             | 改為收貨店庫存,寫「調入」事件,單張成本 = 該列批購金額 ÷ 張數                        |
| 核准前               | 全部點收,且收貨店已付淨額 = 調貨金額                                                |
| 退回 / 撤回後        | 還沒出貨的解除鎖定;已在途的保持在途;結算紀錄保留                                    |
| 在途的列被刪除       | 待查,責任分店 = 出貨店                                                              |
| 駁回前               | 已有點收 → 擋下;兩邊淨額 = 0                                                        |
| 作廢前               | 調入後已售、再調出或拆本 → 擋下;兩邊淨額 = 0                                        |
| 駁回後 / 作廢後      | 全部回到出貨店,寫反向事件;叫貨單回到待購買                                          |

- 送錯分店同進貨單。
- **結算**:第 9 章;出貨店收款不擋完成。
- 報表:收貨店成本 = 調貨批購金額;出貨店顯示「調貨損益」= 調貨金額 − 原成本。
- 列表欄位:單號、出貨店 → 收貨店、本數 / 張數、調貨金額、點收進度、結算、狀態。**列印**:調貨出貨單、調貨付款收據。

### 8.5 撤銷售出申請(店面管理)

| 欄位       | 規則                                                                    |
| ---------- | ----------------------------------------------------------------------- |

| 退款給客人 | 是 / 否;依預設選項代碼自動帶入(客人退貨 = 是),可改;租戶新增的原因帶入否 |

### 8.7 結帳確認申請(店面管理;交班 / 日結)

- 列表欄位:單號、分店、收銀點、類型、應有、實點、差額、狀態。列印結帳單(交班人、接班人簽名;日結由店長簽)。

## 9. 收付機制(刮刮樂內部共用)

- 單據登記:類型名稱、應付金額算法、哪一邊用哪條權限、可用付款方式。API:`recordSettlement`、`reverseSettlement`、`outstandingSettlements`。元件 `SettlementPanel`(進貨、調貨檢視頁共用;待結清款項頁的按鈕開同一個視窗)。
- 寫入 `lottery_bank_transactions` 或 `lottery_cash_movements`,`refType / refId / refRevision` 指回單據;金額一律正數;每一筆有歸屬分店。

| 單據   | 一邊           | 按鈕                                                            | 寫入                                                   |
| ------ | -------------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| 進貨單 | 總部           | 送出時自動第一筆;[付款](批貨支出)、[收到退款](批貨收入)、[沖正] | 銀行                                                   |
| 調貨單 | 收貨店(點收頁) | [付款](調貨支出)、[收到退款](調貨收入)、[沖正]                  | 銀行,或現金(來源:有開著班的收銀點抽屜 / 小金庫;收款人) |
| 調貨單 | 出貨店(檢視頁) | [收款](調貨收入)、[退款](調貨支出)、[沖正]                      | 一律銀行,備註對方是否付現                              |

- 可以分次;付款金額預設 = 已點收 − 已付。共用帳戶時兩邊各記一筆(帳戶淨額 0)。
- 計算:已付淨額 = 支出 − 收入;已收淨額 = 收入 − 支出;待收 = 調貨金額 − 出貨店已收;「其中對方已付」= 收貨店已付 − 出貨店已收(例:「現金 6,000,1/20 交給王○○,出貨店尚未入帳」)。
- 人工登記的帳要人工沖正;已有結算紀錄的單據作廢 / 駁回前淨額必須 = 0。
- 待結清款項:進貨與調貨同一頁;欄位 單據、分店、對象、應付、已付、差額(待付 / 待退 / 待收)、已過天數;每列可直接操作;側欄計數。
- 銀行 [登記交易] 選「批貨收入 / 調貨收入」時,單據欄必填,只列有待退或待收的單據。
- 「兌獎入帳」不算進任何單據的已付 / 已收淨額;進貨單重新送出時兌獎金額有改,不自動調整,記錯的用沖正、少記的到銀行 [登記交易] 選「兌獎入帳」補登(單據欄選填)。

## 10. 帳戶管理 `accounts`

### 10.1 銀行帳戶與交易

**`lottery_bank_accounts`**:orgId(= 租戶)、bankCode、branchName、accountNo、accountName、openingBalance、openingDate、status(使用中 / 停用)、note。唯一 `(tenantId, bankCode, accountNo)`。使用組織 `org_lottery_bank_account`(可多個)。

- 可見範圍:總部人員看得到全部;分店的人看得到使用組織包含自己的帳戶(範圍提升 + 明列 id 讀取)。登記交易另需 `record-bank-transaction`,沖正需 `reverse-bank-transaction`。
- 修改帳戶需 `edit-bank-account`;**有交易之後銀行代碼、帳號、期初餘額、期初日期鎖定**;戶名、分行、狀態、備註、使用組織隨時可改。
- 餘額不存,即時計算;負數只警告。lookup `lottery_bank_account` 顯示 accountName + 帳號末 5 碼,只列使用中。

**`lottery_bank_transactions`**(只新增):accountId、occurredAt、type、direction(只有調整 / 其他需選)、amount(正數)、branchOrgId(歸屬分店;批貨與調貨必填)、refType、refId、refRevision、reversalOf、summary、note、by、at;索引 `(accountId, occurredAt)`。

| 類型                                  | 方向         |
| ------------------------------------- | ------------ |
| 存入 / 兌獎入帳 / 批貨收入 / 調貨收入 | 收           |
| 提領 / 牌租 / 批貨支出 / 調貨支出     | 支           |
| 調整、其他(說明必填)                  | 使用者選     |
| 沖正                                  | 與原交易相反 |

- 沒有「佣金入帳」:佣金是批購價差,靠賣票收回(第 7.1 節)。其他收入(還沒有正式類型的)用「其他」選收,說明寫來源。

詳情頁:餘額卡、交易清單(每列餘額依時間累加)、[登記交易]、[沖正]、使用組織設定。

### 14.2 規則設定

- 人的規則(用主要分店):每月最多 / 最少畫休、最多連續上班、最多連續休假、兩班之間最少休息時數、畫休開放期間。
- 店的規則(用那家店):同日最多畫休人數、`entryMatchToleranceMinutes`(開班對應容許時間,預設 60)、`autoDemandWeekTemplateId`。
- 出勤:`lateGraceMinutes`、`earlyLeaveGraceMinutes`(預設 5)。
- 總部預設,分店可覆寫;每條顯示「沿用總部:8 天」或「本店自訂:6 天」;權限 `edit-default-rules` / `edit-org-rules`。

### 14.3 排班人員(排班設定)

列出操作者看得到的使用者;勾選多人 [加入排班];點一人設定僱用類型、可以排的分店(各店:可擔任負責人、主要分店)。有排班檔案、且可以排的分店包含這家店的人才是候選人(手動與自動同一份名單)。

### 14.4 人力需求與範本

人力需求 = 某店某崗位某時間需要幾人(負責人 + 協同)。套用:單一範本照常加入(略過同日同崗位同時間);週範本與自動排班只補完全沒有人力需求的日子。

### 14.5 排班作業 `schedule.manage`

- 分店選擇器;人 × 日期排班表(底座 `RosterGrid`);套用範本、手動新增;即時檢核畫休、店休、規則、人力不足(「需 3、可排 2」紅色);其他分店的班顯示灰色(看不到那家店時只顯示「已排於其他分店」)。
- 草稿 → 發布;發布後的異動必須選原因並寫 `schedule_changes`。
- **自動排班**:條件可勾選並排序(延續同一人的排班、負責人次數多者優先、本月班數平均;都不勾則隨機);只填人力需求;方式:只填空位 / 重排自動排入的人 / 全部重排(再確認);只能在草稿;畫休、店休、擋下的規則一定遵守;填不滿列出原因;「清除自動排入的人」;結果與檢核在常駐檢核面板;seed 可指定、排序固定、記錄演算法版本。
- 分頁:排班表 | 畫休總覽 | 行事曆(店休擋下排班;特殊日只做背景色)。

### 14.6 我的班表 `schedule.my`

- 月曆(底座 `MonthCalendar`)顯示自己已發布的排班;**我的畫休**:開放期間內畫休,符合規則才存,顯示每天已有幾人畫休;不需要核准;截止後由有 `schedule.manage.edit-day-offs` 的人代改,原因必填。
- **打卡**(`schedule.my.punch`):在排班卡片上打卡(上下班按鈕同時顯示);只顯示今天的班 + 昨天未打下班卡的班;「沒有排班」區塊(今天有班時收合);跨店不限;上班取最早、下班取最晚;頂部提醒最近 7 天打卡不完整並附 [申請補卡];缺卡不存,顯示時計算;登記裝置第二階段才做。

### 14.7 出勤紀錄 `schedule.attendance`

分頁:依人員(月)/ 依分店(日);沒有 `view-all` 只看自己;Excel 每家分店一個工作表:排班、上班、下班、在班時數、休息、實際工時、排班工時、遲到、早退、特殊日類別、補卡註記;不做薪資計算。

### 14.8 補打卡申請(綁在 `schedule.attendance`)

- 欄位:日期、分店、類型(上班 / 下班)、時間、原因(補打卡原因)。入口:出勤紀錄頁 [補打卡申請],或在某筆出勤紀錄上按 [補打卡] 自動帶入日期。
- 流程:一關,店長限定「分店」(B3)。完成時寫入打卡,source = 補打卡。

### 14.9 與刮刮樂的串接

- 排班模組提供查詢「某人在某店某時間的排班」:以 `entryMatchToleranceMinutes` 為容許範圍,有多筆時選開始時間最接近的。
- 開班時刮刮樂呼叫此查詢 → 寫入 `scheduleEntryId` 與職責快照;找不到標示「未對應排班」;開班畫面可改選。
- 收銀點的對應崗位 ≠ 該人職責所對應人力需求的崗位 → 只提醒「你今天排的是補貨,確定要在店內櫃台開班嗎?」並記錄。
- 排班表上崗位旁顯示對應的收銀點名稱(由刮刮樂登記提供)。

### 14.10 支援需求單(綁在 `schedule.manage`)

- 分店人力不足時請總部協助:欄位 日期、時段、崗位、需要人數、說明。
- 流程:一關,店長限定租戶(人員條件:角色 店長 且 所屬組織屬於租戶);總部在排班作業排好人後核准。
- 支援指派單已取消:看得到兩家店的人直接在排班作業排人。

### 14.11 通知(底座 B7 / B14)

畫休開放、截止前一天通知;排班發布通知;發布後的異動通知當事人。都是當事人通知,見第 3.4 節。
