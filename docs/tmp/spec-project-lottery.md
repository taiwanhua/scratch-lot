# 專案規格:刮刮樂 + 排班與出勤

> 狀態:草稿,待使用者審閱。實作在刮刮樂專案 repo `C:\project\scratch-lot`(底座與專案都在這裡做)。底座機制(B1 至 B18、第 19 至 26 項、人員條件)的設計與實作見 `docs/tmp/spec-base-round.md`(以下稱「底座規格」);本文件只寫**本專案怎麼設定與使用**。
> 原則:一個東西只有一個名詞;金額一律正數、由類型表示方向;紀錄只新增、更正用反向紀錄;一個使用者動作 = 一個 Mongo 交易(底座 B13),寄信 / 通知 / 信號 / 列印在交易成功後執行。

## 0. 範圍與模組歸屬

> **S2 測試案例**(見底座規格 0.3a):底座的 B10 全域掃描監聽、欄位選項顏色、B11 報表登記,這一輪**先在本專案階段以專案客製實作**(`project/` 路徑、客製替換、專案 seed),回收前再升格到底座。本文件引用它們的地方照常寫,實作位置以底座規格 0.3a 為準。

| 模組       | 歸屬               | 說明                                                                     |
| ---------- | ------------------ | ------------------------------------------------------------------------ |
| 刮刮樂     | 專案模組           | 本文件第 1~13 章                                                         |
| 排班與出勤 | **獨立的專案模組** | 本文件第 14 章;不引用刮刮樂的任何資料表,將來可給其他行業使用或回收到底座 |

- **依賴方向:刮刮樂 → 排班**。刮刮樂呼叫排班提供的查詢(「某人在某店某時間的排班」);排班不知道刮刮樂存在。排班表上顯示收銀點名稱,是刮刮樂以登記方式提供給排班畫面的。
- **畫面尺寸**:專案畫面都支援電腦、平板、手機;能 RWD 就 RWD,版面差太多時才 AWD(例:排班表在手機改成依日期的清單)。標準列表、表單、詳情頁照第 16.0 節的共用規則;客製畫面三種尺寸各自設計。
- 每個專案 repo = 底座 + 一個專案。本專案的 lookup 來源 key、資料表一律加前綴:刮刮樂 `lottery_`、排班 `schedule_`。

| 店長     | 店面管理全部(含 `bank-deposit` 存銀行)、庫存管理(不含 `edit-allocations`)、四張單據、叫貨、進貨點收、調貨、待結清款項、即時現金帳、輸出報表、收銀點;**不含** `record-bank-transaction` / `reverse-bank-transaction`、主檔修改、`close-period` |

### 3.4 通知類型

依底座 B7:**當事人通知**的收件人由事件決定;**負責人提醒**的收件人 = 類型宣告的組織範圍 且 符合人員條件,租戶可在底座「通知設定」頁調整人員條件。

| 類型                  | 類別       | 組織範圍                                           | 預設人員條件 / 收件人                     | 觸發                                                |
| --------------------- | ---------- | -------------------------------------------------- | ----------------------------------------- | --------------------------------------------------- |
| 日結逾期              | 負責人提醒 | 該分店本身                                         | 角色 店長                                 | B14 每天早上,有已送出交班結帳的班還沒被日結涵蓋計算 |
| 調貨出貨通知          | 負責人提醒 | 收貨店本身                                         | 角色 店長                                 | 調貨單第一關通過(含跳過)                            |
| 證照到期              | 負責人提醒 | 乙類:對應分店含上層(沒有對應分店 → 租戶);甲類:租戶 | 角色 店長                                 | B14 每天,到期前 30 天起                             |
| 牌租繳費提醒          | 負責人提醒 | 乙類對應分店含上層(沒有對應分店 → 租戶)            | 角色 店長                                 | B14,繳費日前 3 天與當天各一次                       |
| 關帳逾期              | 負責人提醒 | 租戶                                               | 角色 店長 且 持有 `accounts.close-period` | B14 每月 3 號,上個月還沒關帳                        |
| 進貨送錯分店          | 當事人通知 | —                                                  | 這張進貨單的建立者                        | 刷到的分店按 [通知總部更正]                         |
| 畫休開放 / 截止前一天 | 當事人通知 | —                                                  | 可以排這家店的排班人員                    | B14                                                 |
| 排班發布              | 當事人通知 | —                                                  | 被排到的人                                | 發布                                                |
| 排班異動              | 當事人通知 | —                                                  | 異動牽涉的人                              | 發布後的異動                                        |

## 6. 店面管理 `store`

### 6.0 共通:精靈、立即生效的操作、哪些動作影響帳

**精靈是一次做完的事**(交班精靈第 6.9 節、日結精靈第 6.10 節):

- 步驟之間的資料只放在畫面狀態,不寫資料庫;重新整理就從頭開始;[取消] 或關掉不留任何資料;沒有草稿、沒有暫存。
- 按 [送出] 時一次寫入:結帳單、盤點單、結帳確認申請在同一個交易。
- 例外是**獨立的立即操作**:補登售出、補登兌獎在精靈或盤點頁裡按下就立即生效、不用審核,和看板上的手動標記售出、兌獎完全一樣;之後取消精靈也不會退回。畫面上這類按鈕旁註明「立即生效」。

  - 按 [最近售出] / [最近兌獎] 打開清單:電腦右側抽屜(✕、點抽屜外面、Esc 關閉);平板右側抽屜(✕、點抽屜外面關閉);手機底部面板,上方有拉桿(✕、往下滑、點面板外面關閉)。撤銷一筆後清單不關,那一筆改顯示「已撤銷」。
  - 開班中的**其他收銀點**:只顯示狀態;那一班的負責人是自己時,另顯示 [切換到這個收銀點](切換本機收銀點,和頂部切換相同)。
- **點卡片原地展開**:電腦 / 平板在卡片原位置往下展開、占滿整列寬度;手機用底部面板(可拉成全螢幕,上方有拉桿;✕、往下滑、點面板外面關閉)。一次只展開一張;點別張、Esc、[收合](手機是 ✕)收起。展開中的卡片用主色框。
  - 展開區頁首:遊戲、本號、剩餘 / 總張數、[本的詳情] [收合]。
  - 格子用 `TicketGrid`(第 7.5 節,與本的詳情頁同一套)。一本分放在多個收銀點時,在別的收銀點的張用「在別的收銀點」樣式(第 7.5 節,不能選),收銀點名稱用 tooltip 顯示(電腦滑過、手機長按);格子上方放共用圖例,格子旁不另寫說明;本班售出的張可以選(用來撤銷)。
  - 選張後格子上方出現操作列「已選 N 張 #…」+ [取消選取],按鈕依選到的狀態與卡片所屬收銀點:
    - 本機收銀點 · 未售 → [標記售出](開確認視窗:選了哪幾張、合計金額、原因;原因必選,預設「刷不到條碼」)[移櫃] [收回];
    - 本機收銀點 · 本班售出 → [撤銷售出](只限本班售出的張;符合當下撤銷條件直接撤銷,否則改送撤銷售出申請);
    - 本機收銀點 · 待查 / 遺失 → [尋回];
    - 其他收銀點 · 未售 → [移櫃] [移櫃並售出](照刷條碼的流程,第 6.3 節);
    - 其他收銀點 · 其他狀態 → 只顯示狀態;
    - 選到不同狀態只顯示共同可用的按鈕。
  - 更正跳號、報廢留在本的詳情頁。展開時刷條碼照常可用,刷到的張在格子裡閃一下。
- 切換本機收銀點時,這台裝置還有自己開著的班 → 先確認「之後的兌獎、投庫、出庫都算到 <收銀點>」。
- [開班] 開彈窗:期初零用金(帶入,唯讀,顯示來源:出庫單或上一班「留給下一班」)、對應排班(必選:系統找到的排班可改選,或「沒有排班(臨時代班)」,第 14.9 節)、崗位不一致的提醒、還沒打上班卡時的打卡提示卡。
- 卡片 = 某本 × 某收銀點的檯面:遊戲名稱、左側色條(都用遊戲設定的顏色,第 5.1 節)、面額、本號、剩餘 / 總張數、今日售出;剩很少的提示。
- 統計列**只顯示本班**的售出張數與金額。
- 距離上次盤點超過 24 小時,頂部提醒「建議盤點一次」。

### 6.3 銷售、快速銷售、當下撤銷

- 刷條碼:底座 B10 全域掃描監聽。看板頁用途 = 銷售;其他沒有宣告用途的頁面刷到刮刮樂 → **快速銷售**小視窗(Enter 確認、Esc 取消)。
- 輸入方式:條碼槍、相機、背面編號 `5164-1-056527-099-0-6`、正面編號 `056527-099` / `056527099`、正面條碼 `0056527099`。
- 銷售條件:裝置設定了本機收銀點、該收銀點有開著的班、使用者有 `store.sell`;不符合只顯示這張刮刮樂的資訊。
- **錢算在哪一班**:刮刮樂在本機收銀點檯面 → 本機收銀點的班。刮刮樂在別的收銀點檯面,而那個收銀點有開著的班、負責人是自己 → 直接算那一班,不用移櫃(提示「已售出 · 店外攤位」)。其他情況 → 提示「這張刮刮樂在店外攤位,確定在店內櫃台售出?」→ 確認後寫「移櫃」+「售出」,算本機收銀點的班。
- 售出後提示「已售出 5164-056527-012 $200 [撤銷]」(底座統一的 Snackbar:電腦 / 平板右下角、手機底部滿寬);收銀點標題列的 [最近售出](只在本機收銀點、自己開的班,第 6.2 節)列出自己在這一班 30 分鐘內賣的張,每列有 [撤銷];撤銷後清單不關,那一筆顯示「已撤銷」。
- 刷到時:本號在本店對到兩款以上遊戲 → 選遊戲;不是本店的刮刮樂、已售、跳號、報廢、被單據鎖定 → 擋下;未拆的本 → 詢問是否拆本並售出(有待標註張數時,先在拆本視窗標好跳號才售出);待查或遺失 → 提示尋回(`inventory.recover`,原因必填,回到刷到的那家店的庫存)。
- 手動標記:在展開的卡片點格子選多張,按 [標記售出] 一次確認;原因必選(欄位管理「手動標記原因」,預設「刷不到條碼」);系統不能用時事後補登也用這個(原因選「系統異常補登」)。
- **當下撤銷**(`store.undo-sale`):自己賣的、30 分鐘內、這一班還開著、那張刮刮樂之後沒有其他異動 → 寫「撤銷」事件,應有現金減少。入口:售出提示的 [撤銷]、[最近售出] 清單每列的 [撤銷]、展開卡片的 [撤銷售出],都先開**撤銷售出確認視窗**「撤銷這張售出? / 5164-056527-012 · 200 元 · 21:52 售出 / 撤銷後 200 元從店內櫃台的抽屜應有金額扣除 / [取消] [撤銷]」。超過 30 分鐘或之後有異動 → 視窗改提示「請改送撤銷售出申請」,按鈕 [取消] [送撤銷售出申請]。兌獎的撤銷規則不同(不限時間、不用審核),見第 6.5 節。

### 6.4 拆本、收回、移櫃

- 拆本:標題列 [拆本] 先列出本店還沒拆的本(也可以刷條碼),選一本後進入拆本精靈(頁首「拆本 · 遊戲 · 本號」+ Stepper,窄螢幕只顯示「第 1 / 2 步 · 名稱」;格子一律每列 10 格):
  - ① 標跳號:只有待標註張數 > 0 時出現(沒有就直接從 ② 開始,Stepper 不顯示);在格子點出不存在的號碼,顯示「已選 2 / 2:#037、#064」,點滿才能 [下一步]。
  - ② 放到哪個收銀點:預設 ● 全部放到 [本機收銀點 ▾](下拉可換);○ 分放到多個收銀點 → 展開格子(跳號反灰不能選),選張後點收銀點分配,下方表格即時列出各收銀點的張號區段與張數;全部的張都分配完才能 [確認拆本]。按鈕 [上一步] [確認拆本]。
- **跳號**:本的迄號大於標準張數時,有「待標註 N 張」。拆本精靈第 ① 步一定要點出不存在的號碼(可多選),點滿 N 張才能進下一步,不能略過;拆本時標註跳號算拆本的一部分,不另需權限。標錯時到本的詳情頁 [更正跳號](第 7.3 節)。跳號的張實體不存在:不算庫存、不算成本、不算損失。
- 收回(檯面 → 庫存)、移櫃(收銀點之間):在展開的卡片選張後操作;寫事件,不需要審核。

### 6.5 兌獎 `lottery_redemptions`

| 欄位                                           | 規則                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| orgId、shiftId、cashPointId                    | 錢從那一班的抽屜付出                                                                  |
| redeemedAt、redeemedBy                         |                                                                                       |
| gameCode、bookNo、ticketNo、rawInput           | 建議刷背面編號                                                                        |
| ticketId                                       | 不是本店的刮刮樂為 null                                                               |
| prizeAmount                                    | 常見金額選項 + 自由輸入                                                               |
| status                                         | 店內持有 / 已送兌 / 已撤銷                                                            |
| purchaseSubmissionId、sentAt                   | 用在哪一張進貨單、送兌時間(第 8.2 節)                                                 |
| revokedAt、revokedBy、revokeReason、revokeNote | 撤銷時間、撤銷人、原因(欄位管理「撤銷兌獎原因」)、說明;當下撤銷的原因固定「當下撤銷」 |
| replacesId                                     | [撤銷並重新登記] 時,新的那筆指向被撤銷的那筆                                          |
| note                                           |                                                                                       |

- 唯一 `(tenantId, gameCode, bookNo, ticketNo)`,只限未撤銷的(partial index):同一張不能兌兩次;撤銷後可以重新登記同一張。
- 單張超過 5,000 元擋下(提示到銀行兌獎);超過抽屜目前應有現金擋下。拿去兌獎是在進貨單勾選(第 8.2 節),狀態從「店內持有」改成「已送兌」。
- **撤銷兌獎**(兩層,都不用審核):
  - **自己登記、這一班還開著**(`store.redeem`):自己就能撤銷,**不限 30 分鐘**;狀態要是「店內持有」。開撤銷兌獎確認視窗「撤銷兌獎? / 5164-056527-031 · 500 元 · 21:50 登記 / 撤銷後 500 元退回店內櫃台的抽屜應有金額 / [取消] [撤銷]」。
  - **那一班已經結帳、或不是自己登記的**(`store.undo-redeem`,預設給店長):確認視窗多一個「撤銷原因」(必填,欄位管理「撤銷兌獎原因」)與說明;那一班還開著 → 應有現金增加;已結帳 → 記成那一班的事後更正。另有 [撤銷並重新登記]:撤銷後直接開兌獎視窗登記正確的那筆,算在同一班(已結帳時同樣記成那一班的事後更正),新的那筆以 `replacesId` 指向原紀錄。寫稽核紀錄。
  - 撤銷後狀態改「已撤銷」,錢退回那一班的抽屜(應有現金增加)。
  - **為什麼不用審核**:撤銷兌獎會讓抽屜的應有金額變多,沒有人能從中得利,所以兩層都直接生效(撤銷售出會讓應有金額變少,所以超過條件要送申請)。
  - **沒有權限的人看不到撤銷兌獎的按鈕**(兌獎提示的 [撤銷]、[最近兌獎] 每列的 [撤銷]、兌獎紀錄詳情的 [撤銷兌獎]),不顯示「請店長…」之類的提示。
  - 入口:兌獎成功提示的 [撤銷] 直接打開那一筆的確認視窗;收銀點標題列 [最近兌獎](只在本機收銀點、自己開的班,第 6.2 節)打開清單(電腦 / 平板右側抽屜、手機底部面板,開關方式見第 6.2 節),列出**自己在這一班登記的兌獎**,每列的 [撤銷] 打開同一個確認視窗,點列的其他地方開兌獎紀錄詳情;drawer 只在按 [最近兌獎] 時打開,兌獎後不會自動打開;兌獎紀錄詳情的 [撤銷兌獎]。
- **已送兌不能撤銷**:要先撤回或退回那張進貨單,狀態回到「店內持有」後再撤銷。
- 兌獎撤銷不走審核。報表與結帳的兌獎金額都扣掉已撤銷的。
- **兌獎紀錄分頁**(`store.view`):篩選 期間、收銀點、狀態(店內持有 / 已送兌 / 已撤銷)、登記人;欄位 時間、收銀點、班次、刮刮樂(遊戲-本號-張號)、金額、狀態、登記人、進貨單;點一列開兌獎紀錄詳情。
- **兌獎紀錄詳情**(對話框):兌獎紀錄分頁點一列、看板 [最近兌獎] 清單點一列(按 [撤銷] 以外的地方)、交班精靈第 ② 步與結帳確認申請的兌獎明細點一列、進貨單勾選的兌獎紀錄點一列。

### 6.6 收銀班次 `lottery_shifts`

| 欄位                 | 說明                                                                          |
| -------------------- | ----------------------------------------------------------------------------- |
| orgId、cashPointId   |                                                                               |
| openedBy、openedAt   | 開班的人就是負責人                                                            |
| openingFloat         | 期初零用金:一天的第一班 = 出庫單金額;其他班 = 上一班「留給下一班」            |
| scheduleEntryId      | 開班時選的排班(第 14.9 節);選「沒有排班(臨時代班)」為 null,標示「未對應排班」 |

- 每個人用自己的帳號;一個人可以同時開多個收銀點的班,但必須是同一家店;協同人員不存在班次上(從排班取得)。

- **改對應排班**:收銀點標題列點負責人那一行 → 班次資訊(開班時間、期初零用金、對應排班、職責與任務內容)→ [改對應排班];只有這一班的負責人或店長、交班結帳送出前可以改;送出後固定。沒有權限的人看不到 [改對應排班]。

### 6.8 盤點 `lottery_stocktakes`

| 欄位                                      | 說明                                                                                                                |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| orgId、type                               | 交班 / 日結 / 臨時                                                                                                  |
| status                                    | 待核准 → 已確認 / 已駁回;退回 → 已退回(臨時盤點:打開時帶入原內容,修改後再送出)。沒有「盤點中」:盤點單在送出時才建立 |
| startedAt、submittedBy/At、confirmedBy/At | 開始盤的時間(畫面上記下)、送出、核准                                                                                |
| lines[]                                   | 每本 × 收銀點:countedAt、方式(點格子 / 掃描)、實盤的張、差異的張與各自的處理                                        |
| unopenedLines[]                           | 未拆的本:在 / 不在                                                                                                  |
| lostReviewLines[]                         | 待查清單的處理:找到了(要刷條碼)/ 確認遺失(`store.confirm-lost`,原因必填)/ 繼續待查                                  |
| summary                                   | 本數、補登售出(張 / 金額)、新增待查、標記異常、確認遺失(張 / 批購成本)                                              |

- 入口:頂部 [盤點](臨時盤點,可選全店或單一收銀點)、交班精靈第 ① 步(那個收銀點)、日結精靈第 ② 步(全店)。
- **盤點頁**(電腦、平板、手機):左欄是本清單,依收銀點分組,每本顯示已盤 / 未盤與異常標記,上方顯示進度「已盤 12 / 18 本」;右欄是選中的本:方式切換(點格子 / 掃描)、系統數字、實盤數、差異張數;本清單之後是「未拆的本」(在 / 不在)與「待查清單」兩個區塊;底部 [差異核對] → 差異列表 → [送出]。手機寬度時本清單改成上方的下拉。
- 盤點只能點格子或掃描(不用數量),每一張的號碼都知道。
- 每本與 countedAt 那一刻的系統數字比對。送出前「**差異核對**」:依本分組列出每一張有差異的張,每張各自處理,可多選後一次套用:
  - 系統未售、實際不在 → [補登售出] / [待查];
  - 系統已售、實際還在 → [標記異常](之後用撤銷售出申請「盤點錯誤」更正);
  - 整本 [重新盤點]。
- **[補登售出] 立即生效**(和手動標記售出相同,不等送出、不用審核;畫面上註明「立即生效」):那個收銀點有開著的班 → 寫「售出」算那一班,應有現金增加;已結帳 → 記成那個收銀點最近一班的事後更正。
- 全店盤點是一張盤點單,明細依收銀點分開記,補登售出各自算到自己收銀點的班,帳不會混。
- 交班盤點只盤那個收銀點;日結盤全店。
- 撤銷審核中的張數標示「撤銷審核中」,不算差異。
- 盤點過程只在畫面上(第 6.0 節):重新整理或離開就從頭盤;[送出] 時才建立盤點單(待核准)。
- **不鎖**:兩人可以同時盤;一天不限次數;待核准的不擋下一次,完成時依時間順序套用。送出時再檢查一次每筆差異,已被其他盤點或操作處理掉的提示「這幾張已被處理,請重新核對」。
- 盤點頁每個收銀點旁有 [補登兌獎] 與那個收銀點目前的「應有現金」(唯讀);補登兌獎立即生效(和看板上的兌獎相同,第 6.5 節),畫面註明「立即生效」。那個收銀點沒有開著的班時 [補登兌獎] 停用,說明「這個收銀點沒有開著的班」。
- 盤點送出不影響現金帳;核准完成時才套用庫存變動(新增待查、確認遺失、尋回、未拆的本不在 → 待查);標記異常只做記號。
- 臨時盤點送「盤點確認申請」;交班與日結的盤點跟著結帳確認申請一起送出、一起核准,也隨結帳確認申請退回。

### 6.9 結帳精靈(交班)與 `lottery_checkouts`

**交班精靈**(一次做完,第 6.0 節):① 盤點(沿用 30 分鐘內 / 現在盤點 / 跳過:`store.skip-stocktake`,原因必填,報表永久標示「未盤點」)→ ② 兌獎(逐筆,可補登;補登兌獎立即生效)→ ③ 抽屜 → ④ 確認 → 送出結帳確認申請,列印結帳單。

```
應有現金 = 期初 + 銷售 − 兌獎 − 投庫 + 出庫 − 調貨支出(現金)+ 調貨收入(現金)− 退貨退款 ± 現金更正
          (逐項列出,每筆可點回單據;只算已完成的單據)
差額 = 實點(依面額清點)− 應有;不為 0 時原因必填(欄位管理「結帳差額原因」)
⚠ 審核中:現金更正 #C-012 +500 / 撤銷售出 #R-008 −500 → 自動帶入差額原因
留給下一班 [金額]  接班人 [使用者](選填)
```

- 接班人選填:「留給下一班」大於 0 時接班人必填;沒有接班人時「留給下一班」必須是 0(錢先投庫),結帳確認申請改由店長審核(第 8.7 節)。

**日結精靈**(第 6.10 節)。

**`lottery_checkouts` 欄位**:orgId、type(交班 / 日結)、cashPointId 與 shiftId(交班才有)、coveredFrom、coveredTo(日結的涵蓋計算期間)、stocktakeId 或 skipReason、應有現金每一項明細、實點(各面額張數)、差額與原因、審核中單據的快照、留給下一班、接班人、小金庫(應有 / 實點 / 差額,日結才有)、存入銀行(金額、帳戶,日結才有)、submissionId。

### 6.10 日結

- 入口:頂部 [日結];**這家店所有收銀點的班都已送出交班結帳**才能按;停用時滑過顯示還沒送出的班。
- **涵蓋計算期間 = 上一次日結送出 ~ 這次日結送出**;期間內送出交班結帳的班由這張日結涵蓋計算。畫面標示「涵蓋計算期間 10/14 09:02 ~ 現在(10/14、10/15 沒有日結)」。**不能補日結**;每一班只會被一張日結涵蓋計算。
- 不屬於任何一班,不會結束任何人的班;送出後再開的班算到下一次日結。
- **涵蓋計算的交班結帳必須全部核准,才能送出日結**(後端送出時再檢查一次)。
- 精靈(一次做完,第 6.0 節):
  - ① **各班結帳**:表格列出涵蓋計算的每一班:收銀點、交班人、送出時間、應有、實點、差額、審核者、狀態(已核准 / 待審核 / 已退回待更正)。審核者是自己的列有 [審核],在側邊打開結帳單直接核准或退回,不離開精靈;審核者是別人的列顯示「等某某核准」;退回的列顯示「待某某更正」。狀態透過頻道 `board:<分店>` 即時更新。全部核准後 [下一步] 才能按,否則顯示「還有 N 班沒核准」。
  - ② 全店盤點(現在 / 沿用 30 分鐘內的全店盤點 / 跳過:`store.skip-stocktake`,原因必填,報表永久標示「未盤點」)。
  - ③ 小金庫(期初 + 投庫 − 出庫 ± 調貨 ± 現金更正 − 存銀行 = 應有;依面額清點、差額、原因)。
  - ④ 存入銀行(金額、帳戶,依使用組織篩選)。
  - ⑤ 確認 → 送出結帳確認申請(類型 = 日結)→ 列印日結單。
- 平常也可以在「班次結帳歷史紀錄」分頁用「待審核」篩選。
- 有已送出交班結帳的班還沒被日結涵蓋計算,而且已經過了隔天早上 → 負責人提醒「日結逾期」(第 3.4 節)、側欄計數。

### 6.11 存銀行

- 入口:頂部 [存銀行],和 [日結] 並列;權限 `store.bank-deposit`(預設只給店長)。店長覺得小金庫的錢太多時,隨時可以存。
- 填寫:金額、存入帳戶(`lottery_bank_account`,使用組織包含這家分店、使用中;只有一個時自動帶入)、備註。
- 同一個交易寫:現金流水「存銀行」(小金庫 → 銀行)+ 銀行「存入」(歸屬分店 = 這家店);列印 58mm 存款單。
- 金額超過小金庫目前的應有金額 → 擋下;實際的錢比系統多時,先用現金更正單補登。
- 不用審核,做完就生效(同投庫、出庫)。
- 記錯:到帳戶管理沖正那筆「存入」,現金流水自動產生反向紀錄。
- 日結第 ④ 步的存入銀行保留,兩邊寫的是同一種紀錄;即時現金帳與報表都列出。

## 8. 單據

### 共通

- 所有單據 = 底座表單 + 流程;掛接點依底座 B1(八個守門、`submitted / stepPassed / returned / withdrawn / completed / rejected / voided`),每個動作一個交易。**被跳過的關卡也觸發 `stepPassed`(skipped: true)**。
- 審核者來源用底座 B3 的人員條件。文中「店長限定 X」= 人員條件「角色 店長 且 所屬組織屬於 X(本身)」,X 是表單欄位、單據所屬組織或租戶;跳過用 B4(指定組織)或既有的跳過條件運算式;自動通過用 B5。
- 作廢一律原因必填(欄位管理「作廢原因」)。
- 列表欄位用底座「列表欄位配置」設定。
- **草稿**:叫貨單、進貨單、調貨單有 [存草稿];撤銷售出申請、現金更正單、補打卡申請、支援需求單沒有(表單設定「允許存草稿」關閉,底座規格第 10.10 節);盤點確認申請、結帳確認申請由流程送出,沒有草稿。
  - 草稿是還沒成立的資料,完全不影響任何正式統計與顯示:不鎖刮刮樂、不入庫、不算預計要給本數,不進報表、待結清、看板、通知;只有建立者看得到。
  - 送出時才檢查(張還能不能調、本數上限等)。
  - 叫貨單、進貨單、調貨單列表有「草稿」狀態與篩選。

### 8.1 叫貨單(叫貨、採購單 `purchasing.requisition`)

| 欄位                                               | 規則                                         |
| -------------------------------------------------- | -------------------------------------------- |
| 叫貨分店                                           | 組織引用;店長預設自己的分店,總部從可見分店選 |
| 期望到貨日                                         | 日期,選填                                    |
| 明細:遊戲(引用 `lottery_game`)、本數(正整數)、備註 |                                              |
| 備註                                               | 多行文字                                     |

- **替換新增頁**:列出**所有販售中的遊戲**(含沒有庫存的新遊戲);本數填 0 的列不寫入;超過預計要給本數只提醒。

```
叫貨分店 [中山店 ▼]   期望到貨日 [____]
[搜尋遊戲名稱或代號____]   面額 [全部 ▼]   ☐ 只看要叫的
┌──────────────────────────────────────────────────────────┐

│ 【新】5198 鼠來寶 100 │    0     │  1   │   —   │   —    │ [ 0 ]  │

│ ...                                                      │
└──────────────────────────────────────────────────────────┘
                                   共叫 3 本,預估批購 $5,520   [送出]
```

| 欄位     | 意思                                                         |
| -------- | ------------------------------------------------------------ |
| 目前庫存 | 這家店這款遊戲現在的張數(未拆的本 + 檯面上的)                |
| 在途     | 本數:叫貨單在「待購買」+ 進貨單 / 調貨單已建立但還沒點收完成 |
| 近 7 天  | 賣出張數                                                     |
| 近 30 天 | 賣出張數                                                     |
| 叫幾本   | 店長填寫                                                     |

- 排序:上市 30 天內的新遊戲排最上面並標【新】(沒填上市日不標);其他依近 30 天賣出由多到少。
- 新遊戲的銷售欄顯示「—」(還沒賣過),不是 0。
- 搜尋名稱或代號、面額篩選;「只看要叫的」只顯示叫幾本 > 0 的列。
- 底部顯示共叫幾本與預估批購金額。**預估批購金額** = Σ(遊戲整本金額 × 遊戲預設批購金額率 × 本數);採購清單同一算法。
- 流程:一關,角色「叫貨審核」;**B4 跳過組織 = 租戶**(總部是分店時改選那家店)。B4 比對的是**申請人**的所屬組織:總部人員替分店送出的叫貨單也會跳過審核。
- 狀態:引擎狀態 + 衍生三種:**待購買**(已完成、未被有效的進貨單或調貨單引用)/ **已進貨**(被有效進貨單引用)/ **已調貨**(被有效調貨單引用)/ 已作廢。一張叫貨單只能對應一張進貨單或調貨單;該單作廢後回到待購買;沒買到的下次重新叫貨。
- 完成時:寫 `lottery_requisition_lines`(分店 × 遊戲 × 本數,唯讀副本);作廢後在副本補 `voidedAt`(不刪除)。
- 列表欄位:單號、叫貨分店、期望到貨日、本數、狀態、建立者。不列印。

**採購清單**(分頁,`purchasing.requisition.purchase-list`)

- 取 `voidedAt` 為空且未被引用的副本列,依遊戲 × 分店加總,顯示預估批購金額;[匯出 Excel](底座 B11 產生器)。
- 每張叫貨單有 [建立進貨單](帶入)與 [從其他分店調貨](開調貨單並引用)。

- **沒有權限時**:沒有 `purchasing.requisition.purchase-list` 看不到「採購清單」分頁;表單四條(新增 / 編輯 / 刪除)沒有就看不到對應按鈕。

### 8.2 進貨單 `purchasing.purchase`

**單頭**

| 欄位       | 規則                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| 進貨分店   | 組織引用                                                                                |
| 叫貨單     | 選填;同一家分店、待購買                                                                 |
| 批購甲類   | `lottery_dealer`,篩選 type = 甲、status = 營業中                                        |
| 本人批購   | 是 / 否                                                                                 |
| 批購受託人 | 本人批購 = 否時必填;B2d 篩選為這位甲類的受託人(`meta.role = trustee`)且啟用             |
| 批購日期   | 預設今天                                                                                |
| 扣款帳戶   | `lottery_bank_account`,使用組織包含進貨分店、使用中;必填;只有一個時自動帶入             |
| 兌獎       | 勾選這次拿去兌獎的兌獎紀錄(只列進貨分店、「店內持有」的);兌獎金額 = 勾選的合計,不能手填 |

**明細**:遊戲(B2b 引用,依條碼帶入;B2c 列內帶入整本金額、批購金額率)、本號、最後張號、張數(唯讀)、整本金額(唯讀)、批購金額率(預設遊戲的值,可逐本改;組標題列可一次改整組;改過的列標色)、批購金額(列內公式)。組標題列顯示該組小計。

**合計**(系統計算,唯讀):

| 項目     | 算法                        | 例      |
| -------- | --------------------------- | ------- |
| 批購合計 | 明細批購金額加總            | 60,000  |
| 兌獎金額 | 勾選的兌獎紀錄合計          | 100,000 |
| 兌獎折抵 | 兌獎金額與批購合計取較小者  | 60,000  |
| 扣款金額 | 批購合計 − 兌獎折抵(最少 0) | 0       |
| 兌獎剩餘 | 兌獎金額 − 兌獎折抵         | 40,000  |

- 送出後:勾選的兌獎紀錄改「已送兌」(記 purchaseSubmissionId、sentAt);撤回、退回、駁回、作廢後回到「店內持有」。跨分店選兌獎紀錄這一輪不做。
- 送出後自動記「批貨支出」= 扣款金額(0 元也要記),這是這張單的應付。
- 兌獎剩餘 > 0 時,同時自動記銀行「兌獎入帳」= 兌獎剩餘,存入扣款帳戶;`refType` 指向這張進貨單方便查來源,但**不算進待結清**(這是兌獎拿回來的錢,不是這張單的款項)。

**頁面**:替換新增頁(刷條碼頁,依遊戲分組;從叫貨單帶入時顯示「叫貨 5,已刷 4」);替換檢視頁 = 引擎零件(唯讀)+ 點收區塊 + `SettlementPanel` + 審核區塊。

**流程**:一關,角色「店長」限定欄位「進貨分店」;店長從申請中心進入,在審核頁逐本刷條碼點收。

| 時機               | 做什麼                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 送出前             | 本號不能和其他有效進貨單或既有的本重複;已點收的列不能被改或刪(用 rowId 比對);叫貨單有效;停售遊戲擋下                                                            |
| 送出後             | 自動記「批貨支出」與(有兌獎剩餘時)「兌獎入帳」(見合計;扣款帳戶、交易時間 = 送出時間、摘要寫批購日、歸屬分店 = 進貨分店);甲類兩個批購日 max 更新;叫貨單 → 已進貨 |
| 重新送出           | 不自動調整;結算區塊顯示待付 / 待退                                                                                                                              |
| 點收一本(非掛接點) | 寫 `lottery_purchase_receipts`(唯一 `(submissionId, rowId)`)、本、張(庫存)、「進貨」事件;單據須在審核中;刷到的最後張號和單上不同 → 擋下「請退回更正」           |
| 核准前             | 還有沒點收的列 → 擋下                                                                                                                                           |
| 完成時             | 不寫帳,不檢查是否結清                                                                                                                                           |
| 駁回前 / 刪除前    | 已有點收 → 擋下;駁回前另要求淨額 = 0                                                                                                                            |
| 作廢前             | 任何一張已售、已調出或已拆本 → 擋下;淨額 = 0                                                                                                                    |
| 駁回後 / 作廢後    | 甲類日期重新計算;作廢另寫「進貨作廢」事件、叫貨單回到待購買                                                                                                     |
| 撤回、退回         | 不擋                                                                                                                                                            |

**錯誤情境**:打錯 → 退回修改沒點收的列;少一本 → 保持審核中,或退回後刪除那一列(差額由結算處理);單上是 B 店、實體送到 A 店 → A 店刷到時擋下,不入庫,提示「這本屬於 B 店的進貨單 #P-xxx,請交給送貨人帶到 B 店,本店不用點收」;[知道了] 不記錄任何東西(書由送貨人帶走,B 店照常點收);單子寫錯(這本其實是給 A 店)時按 [通知總部更正](底座 B7 通知這張進貨單的建立者)。

**列表欄位**:單號、進貨分店、甲類、批購日、扣款金額、點收進度(8/10)、結算(待退 2,000)、狀態。**列印**:進貨點收單。

- **沒有權限時**:沒有 `purchasing.purchase.settle` 看不到結算區塊的 [付款] [收到退款] [沖正]。

### 8.4 調貨單 `purchasing.transfer`

**單頭**:出貨分店、收貨分店(不能相同)、叫貨單(選填,收貨分店、待購買)、備註。

**明細**:遊戲、本(B2d 篩選 `lottery_book`:在出貨店、未被鎖定)、方式(整本 / 選張;只有拆過的本能選張,需要 `partial-tickets`)、張號(區段)、張數、金額(整本 = 整本金額;零碎 = 面額 × 張數)、批購金額率(預設這一本的成本率,可逐本或整組改)、批購金額。合計:調貨金額 = 批購金額合計。

**頁面**:替換新增頁(張數格子 + 刷條碼加入選取);替換檢視頁 = 第一關出貨確認清單;第二關點收(與進貨單共用元件)+ 結算區塊。

**流程**:兩關。第一關 店長限定「出貨分店」,跳過條件 `ctx.user.orgId == 出貨分店`;第二關 店長限定「收貨分店」。收貨店不發起調貨單,缺貨一律開叫貨單。

| 時機                 | 做什麼                                                                              |
| -------------------- | ----------------------------------------------------------------------------------- |
| 送出前               | 本和張都在出貨店,且不在其他未結束的調貨單上                                         |
| 送出後               | 鎖定(lockedBy)= 調貨中,不能賣;叫貨單 → 已調貨                                       |
| 第一關通過後(含跳過) | 位置改「在途」、寫「調出」事件;列印調貨出貨單;負責人提醒「調貨出貨通知」(第 3.4 節) |
| 點收一本             | 改為收貨店庫存,寫「調入」事件,單張成本 = 該列批購金額 ÷ 張數                        |
| 核准前               | 全部點收,且收貨店已付淨額 = 調貨金額                                                |
| 退回 / 撤回後        | 還沒出貨的解除鎖定;已在途的保持在途;結算紀錄保留                                    |
| 在途的列被刪除       | 待查,責任分店 = 出貨店                                                              |
| 駁回前               | 已有點收 → 擋下;兩邊淨額 = 0                                                        |
| 作廢前               | 調入後已售、再調出或拆本 → 擋下;兩邊淨額 = 0                                        |
| 駁回後 / 作廢後      | 全部回到出貨店,寫反向事件;叫貨單回到待購買                                          |

- 送錯分店同進貨單。
- **結算**:第 9 章;出貨店收款不擋完成。
- 報表:收貨店成本 = 調貨批購金額;出貨店顯示「調貨損益」= 調貨金額 − 原成本。
- 列表欄位:單號、出貨店 → 收貨店、本數 / 張數、調貨金額、點收進度、結算、狀態。**列印**:調貨出貨單、調貨付款收據。

- **沒有權限時**:沒有 `purchasing.transfer.pay` 看不到收貨店的 [付款] [收到退款];沒有 `purchasing.transfer.receive` 看不到出貨店的 [收款] [退款];沒有 `purchasing.transfer.partial-tickets` 時不能選零碎張數。

### 8.5 撤銷售出申請(店面管理)

| 欄位       | 規則                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 分店       | 預設目前組織                                                            |
| 張數       | 刷條碼或張數格子;本店已售、不在其他未結束撤銷單上                       |
| 原因       | 欄位管理「撤銷售出原因」                                                |
| 退款給客人 | 是 / 否;依預設選項代碼自動帶入(客人退貨 = 是),可改;租戶新增的原因帶入否 |
| 退款班次   | 退款 = 是時必填;預設送出人目前的班;只能選本店的班;不能選已關帳月份      |
| 說明       |                                                                         |
| 退款金額   | 這些張數的面額合計(唯讀)                                                |

- 替換新增頁;張數跨多本時依本分組,每本一組張數格子。流程:一關,店長限定「分店」,**B5 申請人是審核者時自動通過**。
- 送出後:張數鎖定;盤點時標示「撤銷審核中」;**送出時列印退貨退款收據**(標示「待核准」,經手人簽名)。
- 完成時:張數改回未售、回到原收銀點,寫「撤銷」事件;現金流水「退貨退款」記在退款班次(班還開著 → 計入應有;已結帳 → 記成那一班的事後更正)。
- 駁回:什麼都不記。**完成後不能作廢**(作廢前一律擋下)。

### 8.6 盤點確認申請(店面管理)

- 欄位:分店、盤點單(引用 `lottery_stocktakes`,唯讀)、彙總、說明。替換檢視頁顯示盤點單明細。
- 流程:一關,店長限定「分店」,B5 自動通過。
- 送出時建立盤點單(待核准)並送出申請;送出前差異都已處理,並再檢查一次每筆差異(已被其他盤點或操作處理掉的提示「這幾張已被處理,請重新核對」)。送出後明細鎖定、銷售照常。退回:盤點單 → 已退回,打開時帶入原內容,修改後再送出。
- 完成時:套用新增待查、確認遺失、尋回、未拆的本不在 → 待查;標記異常只做記號(補登售出、補登兌獎在盤點時已生效)。駁回:盤點單 → 已駁回(已補登的售出不退,錯了用撤銷售出申請「盤點錯誤」)。**作廢前一律擋下**(待查錯誤刷到時尋回)。
- 列表欄位:單號、分店、盤點時間、補登售出、新增待查、確認遺失、狀態。

### 8.7 結帳確認申請(店面管理;交班 / 日結)

- 從精靈送出,列表沒有 [+ 新增];欄位見 6.9;替換檢視頁顯示結帳單明細。
- 流程兩關,依類型跳過:交班 → 審核者 = 「接班人」欄位,照常審核(B 當面點過零用金後核准 = 確認);沒有接班人 → 店長限定「分店」;日結 → 店長限定「分店」,**照常審核**。
- 送出前:交班 → 這一班沒有其他審核中的結帳;日結 → 涵蓋計算的交班結帳全部已核准(第 6.10 節)。送出後:交班時這一班結束;結帳單鎖定。
- 完成時:套用盤點結果;交班 → 零用金成為下一班期初(B 已先開班時,先用 A 填寫的金額,被退回修正跟著更新);日結 → 寫現金流水「存銀行」與銀行「存入」。
- **駁回前、作廢前一律擋下**,只能退回。
- 列表欄位:單號、分店、收銀點、類型、應有、實點、差額、狀態。列印結帳單(交班人、接班人簽名;日結由店長簽)。

## 9. 收付機制(刮刮樂內部共用)

- 單據登記:類型名稱、應付金額算法、哪一邊用哪條權限、可用付款方式。API:`recordSettlement`、`reverseSettlement`、`outstandingSettlements`。元件 `SettlementPanel`(進貨、調貨檢視頁共用;待結清款項頁的按鈕開同一個視窗)。
- 寫入 `lottery_bank_transactions` 或 `lottery_cash_movements`,`refType / refId / refRevision` 指回單據;金額一律正數;每一筆有歸屬分店。

| 單據   | 一邊           | 按鈕                                                            | 寫入                                                   |
| ------ | -------------- | --------------------------------------------------------------- | ------------------------------------------------------ |
| 進貨單 | 總部           | 送出時自動第一筆;[付款](批貨支出)、[收到退款](批貨收入)、[沖正] | 銀行                                                   |
| 調貨單 | 收貨店(點收頁) | [付款](調貨支出)、[收到退款](調貨收入)、[沖正]                  | 銀行,或現金(來源:有開著班的收銀點抽屜 / 小金庫;收款人) |
| 調貨單 | 出貨店(檢視頁) | [收款](調貨收入)、[退款](調貨支出)、[沖正]                      | 一律銀行,備註收貨店是否付現                            |

- 可以分次;付款金額預設 = 已點收 − 已付。共用帳戶時兩邊各記一筆(帳戶淨額 0)。
- 計算:已付淨額 = 支出 − 收入;已收淨額 = 收入 − 支出;待收 = 調貨金額 − 出貨店已收。
- **`SettlementPanel` 版面**:上方一列金額(調貨單:調貨金額、收貨店已付、出貨店已收、待收;進貨單:應付、已付、差額);收貨店已付 > 出貨店已收時顯示提示「N 待出貨店入帳」。下方是**收付歷程**:每筆一列,標明哪一店記的、類型、付款方式、金額、經手人 / 收款人、登記人;還沒登記的一方顯示「尚未登記收款 [收款]」。不用「對方」這類要看情境才懂的字。
- 人工登記的帳要人工沖正;已有結算紀錄的單據作廢 / 駁回前淨額必須 = 0。
- 待結清款項:進貨與調貨同一頁;欄位 單據、分店、對象、應付、已付、差額(待付 / 待退 / 待收)、已過天數;每列可直接操作;側欄計數。
- 銀行 [登記交易] 選「批貨收入 / 調貨收入」時,單據欄必填,只列有待退或待收的單據。
- 「兌獎入帳」不算進任何單據的已付 / 已收淨額;進貨單重新送出時兌獎金額有改,不自動調整,記錯的用沖正、少記的到銀行 [登記交易] 選「兌獎入帳」補登(單據欄選填)。

## 10. 帳戶管理 `accounts`

### 10.1 銀行帳戶與交易

**`lottery_bank_accounts`**:orgId(= 租戶)、bankCode、branchName、accountNo、accountName、openingBalance、openingDate、status(使用中 / 停用)、note。唯一 `(tenantId, bankCode, accountNo)`。使用組織 `org_lottery_bank_account`(可多個)。

- 可見範圍:總部人員看得到全部;分店的人看得到使用組織包含自己的帳戶(範圍提升 + 明列 id 讀取)。登記交易另需 `record-bank-transaction`,沖正需 `reverse-bank-transaction`。
- 修改帳戶需 `edit-bank-account`;銀行代碼、帳號、戶名、分行、狀態、備註、使用組織隨時可改(只改主檔,交易用帳戶 id 指向帳戶;寫 audit_log;關帳快照不回頭改);**有交易之後期初餘額、期初日期鎖定**。
- **沒有任何交易的帳戶可以刪除**(`edit-bank-account`);有交易只能停用。
- 餘額不存,即時計算;負數只警告。lookup `lottery_bank_account` 顯示 accountName + 帳號末 5 碼,只列使用中。

**`lottery_bank_transactions`**(只新增):accountId、occurredAt、type、direction(只有調整 / 其他需選)、amount(正數)、branchOrgId(歸屬分店;批貨與調貨必填)、refType、refId、refRevision、reversalOf、summary、note、by、at;索引 `(accountId, occurredAt)`。

| 類型                                  | 方向         |
| ------------------------------------- | ------------ |
| 存入 / 兌獎入帳 / 批貨收入 / 調貨收入 | 收           |
| 提領 / 牌租 / 批貨支出 / 調貨支出     | 支           |
| 調整、其他(說明必填)                  | 使用者選     |
| 沖正                                  | 與原交易相反 |

- 沒有「佣金入帳」:佣金是批購價差,靠賣刮刮樂收回(第 7.1 節)。其他收入(還沒有正式類型的)用「其他」選收,說明寫來源。

詳情頁:餘額卡、交易清單(每列餘額依時間累加)、[登記交易]、[沖正]、使用組織設定。

- **沒有權限時**:沒有 `accounts.view-bank-accounts` / `view-cash` / `view-outstanding` 看不到對應分頁;沒有 `accounts.create-bank-account` 看不到 [+ 新增帳戶];沒有 `accounts.edit-bank-account` 看不到 [編輯];沒有 `accounts.record-bank-transaction` 看不到 [登記交易];沒有 `accounts.reverse-bank-transaction` 看不到 [沖正];沒有 `accounts.close-period` 看不到 [關帳]。

### 10.2 即時現金帳與 `lottery_cash_movements`

**欄位**:orgId、at、by、type、from、to(抽屜 / 小金庫 / 銀行 / 外部)、cashPointId、shiftId(發生班次)、attributedShiftId(只有現金更正)、amount(正數)、refType、refId、payee、note、reversalOf、bankTransactionId。

| 類型                                              | 從 → 到                         |
| ------------------------------------------------- | ------------------------------- |
| 出庫(原因:開班零用金 / 補零錢 / 其他)             | 小金庫 → 抽屜                   |
| 投庫                                              | 抽屜 → 小金庫                   |
| 存銀行(日結第 ④ 步,或 [存銀行])                   | 小金庫 → 銀行(連到銀行「存入」) |
| 調貨支出 / 調貨收入                               | 抽屜或小金庫 ↔ 外部             |
| 退貨退款                                          | 抽屜 → 外部                     |
| 現金更正(增加 / 減少)                             | 外部 ↔ 抽屜或小金庫             |
| 已刪除的類型:交接、調整、開班領零用金、單據付現。 |

- 銀行「存入」被沖正時,連結的「存銀行」流水自動寫一筆反向紀錄(`reversalOf`)。

**畫面(只能查看)**:分店選擇器;上方是小金庫與各收銀點抽屜目前的應有金額;下方是流水清單(類型、收銀點、日期篩選;每筆可點回單據)。小金庫起算點 = 最近一次已完成的日結清點。

見第 9 章。

### 10.4 關帳 `lottery_period_closes`

| 欄位                     | 說明                                                          |
| ------------------------ | ------------------------------------------------------------- |
| tenantId、month(YYYY-MM) | 唯一 `(tenantId, month)`                                      |
| closedAt、closedBy、note |                                                               |
| snapshot.bankAccounts[]  | 每個帳戶月底餘額                                              |
| snapshot.stores[]        | 每家分店:小金庫、各收銀點抽屜餘額、**沒有被日結涵蓋計算的班** |

- 範圍:**整個租戶**;依序關帳;只能關已結束的月份;**永遠關到該月最後一刻**(與按下的時間無關);不能重新開帳。
- 檢查清單:那個月所有收銀班次都已結帳(擋);沒有「審核中且會記到那個月」的單據(擋);每一班都被日結涵蓋計算(只警告,記入快照)。

- 每月 3 號 B14 檢查上個月未關帳 → 負責人提醒「關帳逾期」(第 3.4 節)。
- **更正**:上個月的錯誤用原本的功能在現在記錄(銀行 [沖正] + [登記交易]、現金更正單、撤銷售出、尋回、報廢);只要紀錄指向已關帳月份(沖正原交易、歸屬班次、撤銷的原售出),報表自動歸到「前期更正」。只有使用者自己選時間的欄位(退款班次、現金更正位置、開班改選的排班)要檢查不能選已關帳月份。

- 排班人員**不是新建人**:從使用者管理已有的帳號挑人 [加入排班],建立排班檔案(和使用者一對一);找不到人時先到使用者管理新增帳號(列表底部有連結,有使用者管理權限才顯示)。

- 有排班檔案、且可以排的分店包含這家店的人才是候選人(手動與自動同一份名單)。跨店支援由同時看得到兩家店的人設定;看不到的分店不能加。

### 14.4 人力需求與範本

- 人力需求 = 某店某崗位某時間的**一組執行任務**:每筆執行任務 = 職責(負責人 / 協同,程式固定)+ 任務內容(欄位管理「執行任務」,例「店內事務與帳目負責」「店內事務」);負責人 0 或 1 筆、協同 0~10 筆;需要幾人 = 執行任務筆數。一天裡不同時段人力不同時建多筆。
- 排班**填進**執行任務:一筆執行任務只填一個人;一筆排班可以填進多筆執行任務(跨好幾段的人力需求,或同一段時間兼兩個崗位 = 一人顧兩台),同一筆人力需求只能填一筆。
- 人力需求範本 = 一天裡的一個班(不含日期、不分星期幾),內容同樣是一組執行任務,套用時複製;範本沒有休息(休息只在排班,預設值由規則「預設休息」決定)。人力需求週範本 = 星期幾用哪些人力需求範本。都在排班設定維護(`edit-templates`)。上層組織建立的範本,底下各分店都能用,但只有建立它的那一層能改;列表「建立於」顯示組織名稱。
- 建立人力需求有三種方式:
  1. **套用範本**:排班表工具列 [套用範本] → 右側抽屜(手機全螢幕):
     - 種類 ● 人力需求範本 / ○ 人力需求週範本;人力需求範本可多選,人力需求週範本單選。
     - 套用到:多選日期月曆(底座 `MonthCalendar` 多選),**預設整個月全選**,點一下取消;[全選] [全不選] [平日] [週末];每週左邊有勾選框可以勾整週;店休日不能選(停用色);特殊日顯示名稱。
     - 說明文字(灰色小字,依種類切換):人力需求範本「會加入到選取的日子,即使那天已經有其他人力需求;同一天崗位和時間完全相同的會略過。」;人力需求週範本「只會補上完全沒有人力需求的日子;已經有任何人力需求的日子不會變動。要在已有的日子加上人力需求,請使用人力需求範本。」
     - 預覽「將產生 54 個時段,略過 4 個已存在的相同時段」;[取消] [套用]。
     - 規則:人力需求範本同一天**時間和崗位都相同**的(不論哪個範本)直接略過、不提示,只是時間重疊的照常產生;人力需求週範本只補完全沒有人力需求的日子;不同週要用不同週範本時,分兩次套用。
  2. **手動新增**:工具列 [+ 人力需求];週 / 日 / 月檢視點空白處(帶入點到的日期與時間);班表檢視人力需求區點空白格(帶入日期與那一列的範本:時間、崗位、執行任務);排班對話框「加入這天的人力需求」清單底部 [新增一筆人力需求](就地建立,見第 14.5 節;臨時代班走這條)。對話框見第 14.5 節「人力需求對話框」(新增時可勾選「同時存成人力需求範本」)。未套用範本的人力需求在班表上顯示「臨」;要重複用的人力需求請到排班設定建人力需求範本。
  3. **自動排班補上**:見 14.5「自動排班」。
- 不做「複製過去月份」。

  - 格子寫「負1/1 協0/1」(只有協同需求的寫「協1/1」),實心三態同月檢視:已滿灰、缺協同橘、缺負責紅;那天沒有這種班別就空白;店休整欄灰。點人數標籤 → 人力需求對話框;**點空白格 → 新增人力需求**(帶入日期與那一列的範本;滑過顯示淡色「+ 人力需求」,手機在人力需求區展開後點);工具列右上 [+ 人力需求] 保留。
  - 「▾ 人力需求」可以收合;收合時只剩一列彙總「需 5 · 已排 4 / 缺 1 · 可排 2」(顏色取當天最嚴重的狀態)。展開 / 收合存在瀏覽器(每台裝置各自記住)。
  - 電腦、平板預設展開;平板日期區照常左右捲動,班別欄和人員欄一起固定在左。手機(一次 2 天)預設收合成彙總列,點「▾ 人力需求」展開,班別欄寬度同人員欄。
  - 人員格子不變(寫班別簡稱),從人看「誰排了哪一班」,從人力需求區看「哪一班還缺人」。
- **時間軸的人力需求容器**(週、日檢視):
  - 每筆人力需求畫成一個容器(底層),容器標題「早班 · 櫃台 A 08:30–14:30 · 負責 1/1 · 協同 1/2」(**不放休息**:休息只在排班,寫在長條上)。
  - 填進這筆人力需求的排班長條放在容器裡,容器比裡面所有長條高一點;長條上寫人名(負責人的名字套負責人底色)、休息「☕ 90 分」(只寫分鐘數,不畫休息的位置)。
  - **長條對齊實際時間**:週檢視長條的上下緣、日檢視長條的左右端對齊這個人的上下班時間,不是對齊容器;只上一部分時間的長條比容器短;排班時間超出容器的部分,**同一條長條直接延伸出容器**(不斷開、不另畫一個框),超出那段改成淡色底 + 虛線框,長度照樣對齊實際時間。
  - **週檢視排版**:照底座 `ScheduleTimeline` 週模式排版(底座規格 10.11):收起的單位是整筆人力需求(不單獨收起排班);每筆佔條數 = 執行任務筆數(一筆只填一人,不會多排),空的執行任務畫虛線空位(缺協同橘、缺負責紅),長條順序**依職責、同職責先人後缺額**:負責 → 缺負責 → 協同 → 缺協同(同類依開始時間 → 排班人員排序 → id);缺額一人一條,每條寫「缺負責 1」/「缺協同 1」(週檢視直排);排序鍵 = 開始時間 → 崗位排序 → 範本排序 → 建立時間 → id。有收起時當天欄最右邊一條佔滿 0~24 的「+N」長條,框線:收起的需求有缺負責紅、有缺協同橘、否則灰;點了跳出清單浮層(依開始時間列出被收起的需求:簡稱、時間、人數、三態顏色;點一列 → 那筆人力需求對話框;底部 [看整天(日檢視) ›])。日檢視每人一列,不收起。日期表頭只放日期與特殊日名稱。
  - 缺的人用虛線空位表示:「缺負責 1」紅色、「缺協同 1」橘色。
  - 一筆排班填進兩筆人力需求時,每個容器只畫和它重疊的那段(實線),超出容器時間的部分由同一條長條直接延伸出去(淡色底 + 虛線框,不斷開)。
  - **一人顧兩台**:同一筆排班同一段時間填進兩筆人力需求(例:王小明 14:00–22:00 同時是櫃台 A 與櫃台 B 的負責人)→ 兩個容器都畫他的完整長條,長條右上角加小徽章「×2」(和自動排入標記並排、不重疊;圖例「同一筆排班顧多台(×2)」);滑過列出各台的職責與任務內容;班表格子寫「晚 ×2」。
- **休息與畫休**:休息只在排班(長條、班表格子、排班對話框),人力需求與範本沒有休息;一律用咖啡杯圖示 + 分鐘數(「☕ 30 分」「☕ 90 分」,班表格子窄時「☕ 90」),不寫成「1:30」(避免和時間、總工時混淆);畫休一律寫「畫休」並用灰色斜線底;兩者在圖例分開。
- **滑過提示**(電腦、平板;手機沒有滑過,按下時底色加深、放開後直接打開對應的對話框):排班長條 → 姓名、上下班時間、☕ 休息、職責與任務內容(「負責 · 店內事務與帳目負責」)、崗位、自動排入理由(一筆排班填進多筆時逐筆列出);人力需求容器 → 完整標題、執行任務與缺額;缺額空位 → 「+ 排班」;「+N」長條 → 收起的需求與時間;空白處 → 「+ 人力需求」。滑過 / 已選取外觀照底座規格 10.11 互動狀態;班表格子、人力需求區標籤、月檢視標籤同一套。
- **負責人標示**:負責人的名字(或班表格子的班別簡稱)套 success/lighter 底、success/darker 字;不用 ★,已經套底色的地方不再寫「負責人」三字。綠色在班表管理只代表負責人(人數已滿用灰色)。
- **自動排入標記**:自動排班排入的人,在格子 / 長條 / 標籤右上角固定顯示同一個小圖示(四種檢視一致,寫進圖例);手動改過就消失。
- **行事曆標示**:店休整天灰色、不能排;特殊日用它的顏色(標籤色票 `tagPalettes` 的 bg)當背景並顯示名稱,照常可以排。
- **人數檢查**:依時間切段檢查空的執行任務;空的負責任務紅色(缺負責)、空的協同任務橘色(缺協同),列入「人力不足」提醒;一筆執行任務只填一人,不會超過需求(要多一個人 = 在人力需求加一筆協同任務)。可排 = 那段時間沒有畫休(整天或時段不可排)、沒被其他排班占用、可以排這家店的人。
- **跨店與不可排**:別家店的班在那個人的列上顯示灰色區塊「已排於 B 店 14:00–22:00」,那段時間不能點(看不到 B 店時只寫「已排於其他分店」);時段不可排顯示灰色區塊「不可排 09:00–13:00」,那段時間不能排。
- **圖例**:班表管理所有頁面的圖例用同一個圖例元件(色塊或符號 + 文字),不放只有文字的圖例。畫面上每個顏色、圖示、符號、線型都要在同畫面的圖例找到外觀一樣的項目;圖例的每一項在該檢視都會出現;同一顏色 / 符號在整個模組只有一個意思;顏色只用共用色票。畫休用灰色斜線底(和店休、不可排同屬「不能排」,圖例分開寫),特殊日用它在行事曆設定的顏色當背景(從標籤色票 `tagPalettes` 選,底座規格 10.7;示範用 cyan),不用狀態色 info。
- **未對應排班的打卡在月檢視**:用 ⏲ 小圖示(不用圓點,避免和人力需求的點混淆)。

**兩種對話框**(班表管理只有這兩個,新增 / 編輯共用一個;電腦、平板置中對話框,手機全螢幕):

- **人力需求對話框**:
  - 打開:編輯 = 週 / 日檢視點容器標題、月檢視點標籤、班表檢視人力需求區點人數標籤、手機卡片點標題;新增 = 工具列 [+ 人力需求]、週 / 日 / 月檢視點空白處、班表檢視人力需求區點空白格(帶入日期與那一列的範本)。
  - 欄位:日期、時間、崗位;兩塊 Array Field:「負責人」0~~1 列、「協同」0~~10 列,每列選執行任務(新增一列時帶入規則設定的負責人預設 / 協同預設);[+ 負責人](已有一列時停用)、[+ 協同](滿 10 列時停用);每列可以移除。
  - **同時存成人力需求範本**:只在新增時出現、預設不勾;勾了要填範本名稱與簡稱(1~2 字),存檔時同時建立一筆人力需求範本(時間、崗位、執行任務照這筆;範本屬於目前這一層組織,可見 / 修改規則照第 14.4 節既有範本規定);要有 `schedule.settings.edit-templates`;編輯時不顯示。
  - **不選人、不顯示排班**:誰填進哪一筆在時間軸 / 班表看,要改從排班對話框改。
  - 有人填的執行任務可以改任務內容。移除有人填的那一列、或 [刪除人力需求] 時,確認視窗列出會解除的人(「王小明填在這筆,刪除後他的排班不再填這筆」);照「排班至少要填進一筆」的原則,解除後會變成零筆的排班另外列出,按鈕改成 [刪除人力需求並刪除這 N 筆排班] / [取消](移除一列時是 [移除並刪除這筆排班]);其中已被收銀班次綁定的排班不能刪 → 擋下並列出,要先改那筆排班。
- **排班對話框**:
  - 打開:編輯 = 班表點有排班的格子、週 / 日點長條、手機卡片點人;新增 = 班表點空白格(人員、日期已帶入)、週 / 日點缺額空位(帶好那筆人力需求與那筆執行任務)、手機卡片點缺額、工具列 [+ 新增排班]、班表格子的時鐘圖示(那天沒有排班時,見下方未對應排班的打卡)。
  - 欄位:人員(從格子或編輯打開時已帶入、不能改)、上下班時間、休息(新增時依規則「預設休息」帶入,可以改)。
  - 「加入這天的人力需求」清單(Array Field,只列當天的人力需求):每列 = 人力需求 + 職責 + 執行任務。選人力需求時系統自動填第一個空的執行任務:這筆還缺負責、且這個人可以擔任負責人 → 負責;否則第一個空的協同。旁邊的下拉可以改成同一筆其他空的執行任務;已被別人填的停用並寫填的人;同一筆人力需求只能選一次。
  - 清單底部 [新增一筆人力需求]:在排班對話框內就地建立一筆沒有套用範本的人力需求(顯示「臨」):時間預設 = 這筆排班的上下班時間(可以改)、崗位必選,自動建一筆執行任務給這個人(職責預設:這個人可以擔任負責人 → 負責,否則協同;任務內容用規則的負責人 / 協同預設),建好後自動填進。從時鐘圖示打開的臨時代班就走這條。
  - **至少要填進一筆執行任務才能存**:移除最後一列時 [儲存] 停用,提示「至少要填進一筆人力需求;不要這筆排班請按 [刪除這筆排班]」。
  - **時間涵蓋提示(只有職責 = 負責人)**:上下班時間沒有涵蓋那筆人力需求時,那一列下方提示「上下班時間沒有涵蓋晚班 14:30–18:00」+ [往後延長到 18:00] / [往前延長到 13:00](依缺的是哪一端,兩端都缺就兩顆),按了直接改上下班時間。協同可以只上一段,不提示。不提供「另建一筆排班」:要分兩段就新增另一筆排班。
  - [刪除這筆排班]:先確認(填進的執行任務一起解除);**這筆排班已被收銀班次綁定**(第 14.9 節)→ 擋下「這筆排班已經有開班紀錄,不能刪除;要調整請改時間」。
- **未對應排班的打卡**:
  - 標示:班表檢視在那人那天的格子角落顯示時鐘圖示 + 張數(例「🕘 2」);週 / 日檢視在那天的日期旁顯示同一個圖示;月檢視那天格子加 ⏲ 小圖示;圖例元件有這個圖示。
  - 檢核面板多一類「未對應排班的打卡」(等級:提醒,不影響發布),每項「王小明 11/5 · 3 張」,[查看] 捲到那一格並閃爍。
  - 排班對話框的區塊:這個人那天有未對應排班的打卡時多一個區塊,標題「王小明 11/5 有 3 張未對應排班的打卡」,列出當天全部未對應的打卡(時間、上班 / 下班),每張可以勾選;預設勾選排班時間前後 `entryMatchToleranceMinutes` 內的;重複打卡標「重複打卡」、預設不勾;儲存時勾選的打卡一起對應到這筆排班,不勾就不對應。只有上班沒有下班的照樣可以對應,之後出勤紀錄顯示缺卡,由本人申請補卡。
  - 區塊裡的勾選項「上下班時間改用打卡時間」:**預設不勾**(之後算薪水可能一律用排班時間);要有 `schedule.manage.use-punch-time`,沒有權限時不顯示。勾了 → 上下班時間換成勾選的打卡中最早的上班與最晚的下班。
  - 那天沒有排班(臨時代班)→ 點格子的時鐘圖示打開新增排班(人員、日期帶入,同一個區塊);上下班時間自己填,或勾「上下班時間改用打卡時間」(有權限時才看得到,勾了才帶入);當天沒有合適的人力需求時用清單底部 [新增一筆人力需求] 就地建一筆「臨」。
  - 人力需求對話框不選人,不顯示打卡。
- 已發布後,兩種對話框都多一個「異動原因」(必填,欄位管理「排班異動原因」),寫入 `schedule_changes` 並通知當事人。
- **移除這天所有排班**(颱風停班等):日期欄 [⋯] → 確認視窗列出會刪除的排班,原因只填一次;已被開班綁定的排班略過並列出。不加「已取消」狀態;照常上班、雙倍薪水的日子用行事曆標成特殊日(不計算薪資)。

**檢核面板**(右側 persistent 側邊面板,不遮擋;手機是不遮擋的底部面板,可以拉高或收合):

- 開關:工具列最右邊的檢核按鈕,點一下展開 / 收合;面板右上角 ✕。自動排班完成後自動展開。
- 面板打開時:電腦的側欄自動收合成圖示列;班表檢視的統計欄暫時收成一個窄欄 [統計 ▸],點了展開。
- 內容:最上方是最近一次自動排班的摘要(「11/9 14:20 填入 112 人次 · 補上 18 天的人力需求」)與 [清除自動排入的人];篩選 [全部] [限制 N] [提醒 N];每項寫規則名稱與違反的排班(限制在前、各自依規則排序;「未對應排班的打卡」也列在提醒),每項有 [查看]:捲到排班表那一格並閃爍;改完即時更新。
- 用最新生效設定即時檢查,和發布時的檢查一致。

**自動排班**(`auto-run`;只能在未發布):

- [自動排班] → 對話框:範圍(日期範圍,預設整個月)、方式(只填空位 / 重排自動排入的人 / 全部重排)、條件(可勾選、可拖拉排序、整組繼承:延續同一人的排班、負責人次數多者優先、本月班數平均、允許同一人同時段填進多筆人力需求(兼多個崗位,**預設不勾**);排序類的條件都不勾就隨機,平手也隨機)。
- 這家店有設定預設人力需求週範本時,多一個選項「☑ 先以『一般週』補上人力需求」(預設勾選),下方灰色小字用人力需求週範本那段說明文字;有 `auto-run` 就可以補上人力需求,不需要 `edit`。執行順序:先補人力需求,再填人。
- 範圍內沒有任何人力需求、也沒有可以補的週範本 → 顯示「11 月還沒有任何人力需求,請先套用人力需求範本或人力需求週範本」,[執行] 停用。
- 選「全部重排」→ 先確認「將清除 34 個手動排入的人次,確定嗎?」。
- 一定遵守:畫休(整天或時段不可排)、店休、等級為限制的規則;只填空的執行任務,一筆只填一人;負責人的執行任務只填可以擔任負責人的人;排不滿的人力需求列為「人力不足」提醒並寫原因;新增的排班休息依規則「預設休息」。
- **兼多個崗位**:沒勾「允許同一人同時段填進多筆人力需求」時,自動排班不會讓同一人填進時間重疊的兩筆人力需求;一人顧兩台只能手動排(或勾這個條件)。檢核規則「同一時段兼多個崗位」(提醒,預設關閉)是另一件事:條件決定自動排班會不會這樣排,規則決定排好之後要不要列提醒;兩者各自設定,手動與自動排出來的都一樣檢查。
- 執行期間鎖定這個月(其他人看到「自動排班執行中」);結果不用彈窗,回到排班表,檢核面板自動展開。
- **清除自動排入的人**:選日期範圍 → 確認 → 只移除來源 = 自動的填進紀錄(手動改過的已經變成手動,不會被清除);移除後沒有任何執行任務的自動排班一起刪除。不做「復原這次自動排班」。
- 隨機:每次執行由系統產生種子並記在執行紀錄,使用者看不到也不能操作;用可指定種子的產生器,處理順序固定(日期 → 開始時間 → id;候選人依 id),同時記錄演算法版本。

**發布**(`publish`):

- **未發布**:這個月份還沒公開。不是流程的草稿:沒有 [存草稿],對話框按 [儲存] 就存入;員工的「我的班表」看不到,不通知任何人。狀態說明「未發布:員工還看不到這個月的班表。每次儲存都會保存,按 [發布] 後才公開並通知被排到的人」。
- 未發布 → 發布;發布後**不會再變回未發布**(不提供取消發布);發布後仍可修改,存了就直接生效,必填異動原因並通知當事人。狀態說明「已發布:員工看得到。修改會直接生效,要填異動原因並通知當事人」。
- 按 [發布] 時用**發布當下的最新生效設定**重新檢查整個月份(含人力不足):
  - 全部符合 → 確認視窗 [取消] [發布]。
  - 只有提醒 → 確認視窗列出提醒(依規則排序,每列 [查看]:關閉視窗、捲到那一格並閃爍),可以 [仍要發布]。
  - 有違反限制 → 不能發布:確認視窗列出違反的排班(限制在前、提醒在後),[發布] 停用。
- 已發布:工具列狀態顯示「已發布 · 發布日期 發布人」,[自動排班] [發布] 不顯示;通知被排到的人。

**其他狀態與權限差異**:

- 這個月還沒有人力需求 → 排班表位置顯示「11 月還沒有人力需求」與 [套用範本]。
- 沒有 `edit` 時看不到 [+ 人力需求] [+ 新增排班] [套用範本] 與日期欄 [⋯],空白處、缺額空位不能點;點格子 / 長條 / 人力需求只開唯讀的對話框(另畫一張)。
- 沒有 `auto-run` 時看不到 [自動排班];沒有 `publish` 時看不到 [發布]。

#### 畫休總覽(`view-day-offs`)

- 月曆:每天顯示誰整天畫休、誰時段不可排(含時間),同日畫休人數「2/2」(只計入以這家店為主要分店的人;整天或時段不可排都算 1 人;未滿灰、滿了橘、超過紅)。
- 頂部:開放期間「開放中:10/15–10/25,剩 6 天」、尚未畫休 N 人;篩選 [全部] [尚未畫休](列出開放期間內還沒畫任何一天的人)。
- [代改](`edit-day-offs`):選人、日期,種類(整天畫休 / 時段不可排 + 時間);截止後原因必填(截止前不需要);寫入代改人。
- 沒有 `edit-day-offs` 時看不到 [代改]。

#### 行事曆(`edit-calendar`)

- 沒有 `edit-calendar` 時看不到 [新增],點日期只看說明。

### 14.6 我的班表 `schedule.my`

- 分頁:**班表 | 我的畫休**(打卡在「班表」分頁最上方)。以人為單位,跨分店合併顯示,只顯示已發布的班。
- **班表分頁**:
  - **打卡**(`schedule.my.punch`):在排班卡片上打卡,上下班按鈕同時顯示,按哪張卡片就對應哪一筆排班;只顯示今天的班 + 昨天未打下班卡的班;「沒有排班」區塊(今天有班時收合成一行連結「沒有排到班但臨時來上班?」;今天沒班時展開;已經打了未對應排班的上班卡時展開並醒目顯示 [打下班卡]);跨店不限;上班取最早、下班取最晚,多出來的標成「重複打卡」;登記裝置第二階段才做。
  - **打卡不完整提醒**:頂部列出最近 7 天打卡不完整的班(上下班都檢查、只檢查已結束的班),每列附 [申請補卡](帶入資料),已送出的顯示「補卡審核中」;不能手動關閉。缺卡不存,顯示時計算。
  - **最近異動**:有異動才出現的橫幅「你的班表有 2 項異動 [展開]」,展開列出異動(日期、原本 → 現在、原因);只列還沒到的班;「新」以上次打開這一頁的時間判斷(存在瀏覽器);月曆上有異動的日子右上角有小圓點。
  - **月曆**(底座 `MonthCalendar`),**可以換月**(`◀ 2026 年 11 月 ▶`,月份放網址參數):每天顯示自己的排班(分店、時間、負責人標籤)與**打卡紀錄**(上班 / 下班時間);已結束的班缺卡在日期右上角用紅點標示(電腦、平板、手機一致,圖例「● 缺卡」);特殊日用背景色。點一天 → 當天詳情(排班、職責與任務內容、打卡紀錄;缺卡時說明缺了哪張卡並附 [申請補卡];手機用底部面板)。
  - `[月曆 | 條列]` 切換:電腦 / 平板預設月曆,手機預設條列(依日期列出這個月的班與打卡)。
- **我的畫休分頁**(`schedule.my.edit-day-offs`):
  - 開放期間內畫的是**下個月**;不需要核准,符合規則就立即存檔。
  - 只有一個 [登記畫休] 按鈕(點日期也會打開,帶入那天):對話框選「整天畫休 / 時段不可排」,選時段不可排才出現開始 / 結束時間(一天可以多段);已登記的可以刪除。
  - 那天只要有任何畫休(整天或時段不可排)就算 1 天畫休、算 1 個畫休人數。
  - 格子:整天畫休顯示「畫休」(灰色斜線底,任何地方都不縮寫成「休」);時段不可排顯示「09:00–13:00 不可排」;同日畫休人數「2/2」(未滿灰、滿了橘、超過紅);人的規則在違反的日子底部加色帶(紅 = 違反限制、橘 = 提醒);頂部統計列「已畫 4 天 · 上限 8 · 下限 4」;下方違規清單,每項有 [查看]。
  - 點格子的 ⓘ 看當天詳細:誰畫休(看得到人名)、涉及哪些規則;手機用底部面板。
  - 違反限制 → 不存,提示原因。
  - 開放期間外:「畫休登記期間(10/15~10/25)已結束,不能自己修改。要調整請聯絡店長或排班負責人。」;有代改權限的人看到「到 [畫休總覽] 代改」的連結。
- 圖例(負責人底色、「臨」、休息 ☕、畫休斜線、不可排、自動排入、色帶、各種顏色)寫在模組的 help.md,點模組標題旁的問號可以看;畫面上用同一個圖例元件。

### 14.7 出勤紀錄 `schedule.attendance`

- 分頁:依人員(月)/ 依分店(日);員工只看自己的,有 `view-all` 看全店 / 全部;不自動更新,也不放立即刷新按鈕。
- 依分店(日):列出當天排班的人、已到 / 未到、上下班打卡、遲到 / 早退;沒有對應排班的打卡另列「未對應排班」,每列有 [改對應排班];可以勾「只看未對應排班的打卡」篩選。排班作業也可以處理未對應排班的打卡(第 14.5 節)。
- 每筆打卡 [改對應排班](`reassign-punches`,原因必填,留紀錄;對話框標題「修改這張打卡對應的排班」);時間與類型不能改。沒有 `reassign-punches` 時看不到 [改對應排班]。
- Excel(`export`)每家分店一個工作表:排班、上班、下班、在班時數、休息、實際工時(= 下班 − 上班 − 休息)、排班工時、遲到、早退、特殊日類別、補卡註記;不做薪資計算。

### 14.8 補打卡申請(綁在 `schedule.attendance`)

- 欄位:日期、分店、類型(上班 / 下班)、時間、原因(補打卡原因)。入口:出勤紀錄頁 [補打卡申請]、某筆出勤紀錄 [補打卡]、我的班表的打卡不完整提醒或當天詳情 [申請補卡](自動帶入日期、分店、類型)。
- 流程:一關,店長限定「分店」(B3)。完成時寫入打卡(source = 補打卡),對應排班照申請的那一筆。沒有草稿。
- 未對應排班的打卡在排班作業對應到排班後,只有上班沒有下班的照樣顯示缺卡,由本人申請補卡。

### 14.9 與刮刮樂的串接

- 排班模組提供查詢「某人在某店某時間的排班」:以 `entryMatchToleranceMinutes` 為容許範圍,有多筆時選開始時間最接近的。
- **開班一定要選一筆排班**:開班彈窗帶出系統找到的排班(可以手動改選這個人當天在這家店的其他排班);都不是的話選「沒有排班(臨時代班)」,班次標示「未對應排班」。以 `scheduleEntryId` 綁定,同時寫入**任務快照**:在這筆排班填進的執行任務裡,找「人力需求的崗位 = 收銀點的崗位」的那一筆(同一家店崗位和收銀點 1:1;一筆排班在同一筆人力需求裡只能填一筆,所以通常只有一筆;兩筆不同人力需求同崗位又重疊時,先選負責、再選開始較早的),寫入職責 + 任務內容;對不到 → 照既有的崗位不一致提醒並記錄,快照空白。
- 綁定之後,排班改時間、改填進的執行任務都不影響綁定(還是同一筆排班),**不做自動重新對應**;任務快照維持開班時的內容。
- **收銀點的協同** = 同一筆人力需求裡協同任務填的人(從排班取得,不存在班次上)。帳務以收銀點班次為單位不變;報表(班次結帳歷史)顯示負責人 / 協同與任務內容。
- **同一人顧兩個收銀點**:一筆排班同時填進兩筆人力需求的執行任務(櫃台 A、櫃台 B 各一筆);兩個收銀點各自開班時都選同一筆排班,各自找到自己崗位的那一筆寫入快照;打卡只有一組(上班、下班各一次);班數算 1 班、工時算一次。
- **改對應排班**:收銀點標題列點負責人那一行 → 班次資訊 → [改對應排班];只有這一班的負責人或店長,在交班結帳送出前可以改(可以改成另一筆排班,或改成「沒有排班」);送出後固定。改的時候重新寫入任務快照,並記 audit_log。
- **已被收銀班次綁定的排班不能刪除**:排班作業擋下「這筆排班已經有開班紀錄,不能刪除;要調整請改時間」;「移除這天所有排班」也會略過並列出。
- 這筆排班沒有填進收銀點崗位的人力需求 → 只提醒「你今天排的是補貨,確定要在店內櫃台開班嗎?」並記錄(即上面「對不到」)。
- 排班表上崗位旁顯示對應的收銀點名稱(由刮刮樂登記提供)。
- 開班彈窗:這個人今天還沒打上班卡時,上方顯示提示卡「你還沒打上班卡 [打卡]」(`schedule.my.punch`;按了直接打這一班的上班卡)。

### 14.10 支援需求單(綁在 `schedule.manage`)

- 支援指派單已取消:看得到兩家店的人直接在排班作業排人。
- 入口:排班作業的第四個分頁「支援需求單」(列表 + 右側檢視 / 審核,[+ 新增] 開新增頁);平板 / 手機的列表照 RW-01(表格 → 卡片、篩選抽屜)。沒有草稿。

## 17. 必須通過的測試

開票時,相關的票要附上這些測試。共通原則:

- 所有狀態改變用條件更新(狀態 + 版本);同時兩個請求只能一個成功,另一個收到「已被處理」。
- 事件 id = `<id>:<版本>`,重送不會重複寫入(冪等)。
- 應有現金只由事件加總,不另存可被改寫的數字。

以下例子每張 200 元,收銀點「店內櫃台」開著的班期初 5,000。
