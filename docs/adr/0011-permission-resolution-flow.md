# 權限查詢與判斷流程:從登入到畫面渲染的完整鏈路

> 現況說明見 `docs/concepts/authorization.md`「解析流程」「兩道防守」「abilities 的兩種語意」與 `docs/concepts/frontend-architecture.md`「路由與導向」「頁籤兩種」。

本 ADR 決定「查什麼表、組什麼結構、在哪裡判斷」。逐步細節在 concepts,這裡只記決策與理由。

## 資料來源(誰決定什麼)

| 資料                             | 決定什麼                                         |
| -------------------------------- | ------------------------------------------------ |
| `role_module`(核心關聯)          | 進得去哪些頁(模組 = 頁面)                        |
| `role_permission`(核心關聯)      | 頁面裡什麼能用(權限 = 按鈕 / 欄位 / 跳窗 / flag) |
| `permissions.moduleId`(直接欄位) | 每筆權限屬於哪個模組                             |
| `data_scope_rules`               | 查資料時看得到哪些(ADR-0008)                     |

## 登入後的查詢步驟

**決策**:

- api 的 `PermissionResolver` 是單一入口:`user_role` → `role_module` / `role_permission` → 展開同層 `*` → 組**模組陣列**(`me.modules`)。
- 停用的角色不計(授予仍在,只是不生效);停用的權限不算持有,連超級管理員也不給;停用的模組連子樹剔除。
- 持超級管理員到角色那一步即 bypass。
- 模組陣列每筆帶完整 `route`(父段累加)與該模組的有效權限 key;權限容器的 `route` 為 null。
- `@RequirePermission` 守門與 `me.modules` 吃同一份結果。

**理由**:一個入口,API 守門與畫面永遠一致;模組子樹停用時,該處權限也跟著 FORBIDDEN。前端拿到的是已展開的結果,不必自己懂 wildcard 之外的規則。

## 前端判斷

**決策**:

- **側欄**:以 `parentId` 組樹;`sidebarType` 決定呈現。
- **路由防守**:**可進 = 有那個模組路由**,僅此一條。
  - 尾端動態參數的退路:只對 `hidden` 模組試一次「去掉最後一段」,那段當 `routeParam`;`link` 模組不適用。
- **頁內功能**:模組陣列組成全域權限集合,放 react-query 快取;判斷 =「key 在集合中,或擁有模組 key + `.*` 在集合中」。前後端用同一個 `hasPermission`。
- **key 切分共識**:最後一段 = 動作,其餘 = 擁有模組 key。歸屬仍以 `moduleId` 為準,切字串只供人讀與前端組 key。

**理由**:

- 路由只有一條規則,打錯網址與沒權限才分得清。
- 詳情 / 編輯頁的模組路由本身不含識別碼,實際網址卻帶 id;退路只放寬「網址長相」,沒放寬「可進 = 有那個模組路由」。
- `link` 後面多一段就是打錯網址,放寬會讓錯誤網址看起來像頁面。

## abilities 的兩種語意

**決策**:

- 業務模組的 `item.abilities` **已含權限判斷**:前端直接讀,不與 `usePermissions` 相乘。
- 治理模組的 `Role.abilities` **刻意不含權限 key**,只表達角色種類規則:前端與 `usePermissions` 相乘。
- 新模組預設用第一種。只有「同一權限下,每一筆還有各自的可不可以」才用第二種,並在模組文件寫明。

**理由**:同一條規則兩邊各算一次,對不起來就是畫面與 API 不一致;把權限判斷收進 api,前端少一份會走樣的複本。

## API 防守

**決策**:resolver 標註所需權限 key(重用頁面權限 key,ADR-0004),後端同樣以「聯集 + 擁有模組的 `*`」判斷。資料查詢一律經 BaseRepository(租戶保底 + 資料範圍規則)。

## 快取

**決策**:後端 v1 不快取,每次現查(ADR-0003)。前端以 react-query 快取模組陣列;自己的異動主動失效,別人的異動重新整理才看到。

**取捨**:別人改了你的角色,你要重新整理才看到新的側欄;API 端則立即生效,不會多給。

## 路由與導向規則

**決策**:可進入路由集合 = 模組陣列中有 route 的 `link` 與 `hidden` 模組。

| 網址                  | 行為                                                      |
| --------------------- | --------------------------------------------------------- |
| 模組路由              | 顯示該模組頁面                                            |
| 群組路由              | 轉到該群組下側欄順序深度優先第一個 `link`;沒有 → 無權限頁 |
| `/`                   | 整棵側欄樹深度優先第一個 `link`;沒有 → 無權限頁           |
| 隱藏頁路由 + 尾端一段 | 去掉最後一段後對得上 `hidden` 模組才放行                  |
| 其餘                  | 無權限頁(明示是權限問題,不是壞掉)                         |

- 群組路由與 `/` 是同一條規則、同一個函式,只差起點。
- 「總覽」是正式模組,進權限體系、由角色授權;側欄沒有固定列。

**理由**:`/` 與群組都不是頁面;「帶我去第一個能進的頁」一條規則就涵蓋兩者,不必為每種角色寫首頁設定。

## 頁籤兩種

**決策**:判準是「它是不是一個網址」。

- **路由頁籤**(殼的 `RouteTabs`):網址進得去就生成一個,與路由防守同一個比對;以完整網址去重。帶識別碼的詳情 / 編輯頁是詳情子頁籤,項目名由頁面提供,殼不查業務資料。
- **頁內頁籤**(`PageTabs`;切換要被攔下時直接用 `@repo/ui/tabs`):同一個網址裡切換區塊,不進路由頁籤列;目前分頁記在網址參數(`?tab=`,REACT-14),路由頁籤連同參數一起記住。

**理由**:要能分享、重整後回得來、出現在頁籤列的就做成路由;只是同一筆資料的不同面向就用頁內頁籤。判準只有一條,新頁面不必每次討論。
