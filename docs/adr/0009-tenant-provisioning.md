# 租戶開通:自動四步 + 角色模板複製;「模組與權限」根組織專屬

> 現況說明見 `docs/concepts/accounts-and-tenants.md`「租戶開通」起三節;流程與畫面見 `docs/modules/org-manager.md`。

## 開通

**決策**:根組織的操作者在組織管理執行開通,系統自動:

1. 建立租戶 Org(根組織的直接子組織)。
2. 從種子模板複製一份「租戶管理員」角色到該租戶名下,只綁開通表單勾選的模組(預設全勾),每個模組各一筆 `*`。副本以 `roles.settings.templateKey` 標記來源。
3. 建立首任租戶管理員帳號並完成綁定,**不設初始密碼**,寄啟用信由本人設定。
4. 設定租戶擁有者:`orgs.ownerUserId` = 首任租戶管理員。

- 模板 = 全部模組扣除根組織專屬模組(見「其他規則」),每個模組一筆 `*`;永不直接授予。
- 「新增子組織」是另一個輕量入口,不觸發上述流程。

**理由**:

- 各租戶各持一份副本,可自行客製、互不影響。
- 副本就是租戶的天花板:防越權讓租戶管理員只能下放副本裡有的。
- 根組織端不經手租戶密碼。
- 副本沒有 `key`(key 全庫唯一),所以要一個標記認出「哪一筆授予不可解除」。

**影響**:seed 新增模組只進模板,**既有租戶的副本不會自動拿到新模組**,由根組織逐一開放。

## 租戶擁有者

**決策**:

- 「首任」只是來源描述;租戶管理員角色可再授予他人。
- 唯獨擁有者受保護:其租戶管理員授予不可被解除、不可被移出租戶、不可被停用。根組織可執行(處理擁有者失聯等例外)。
- 擁有權轉移只有根組織可操作。
- 租戶頂層本身不可被租戶內的人停用、刪除、搬移;這三件只有根組織能做。
- 可見性開關不是根組織專屬:擁有者或持 `system.org-manager.set-visibility` 者可設自己的租戶(ADR-0005)。

**理由**:租戶至少要有一個一定進得來、管得動的人;保護擁有者就不會出現「租戶把自己鎖在門外」。

## 撤銷開通

**決策**:開錯的租戶不走刪除,另立根組織專屬的反向動作 `revokeTenantProvision`(權限與開通分開兩筆)。它把開通建出的三樣 —— 租戶 Org、角色副本、首任管理員帳號 —— 連同核心關聯一起抹掉。

- 只在「還沒有人用」時允許;前置檢查與刪除共用同一支函式,差別只在擁有者與副本不算數。
- 抹除是**硬刪除**。
- `audit_logs` 不抹;撤銷本身記一筆。

**理由**:

- 刪除走不通:租戶頂層一定有成員(擁有者)、一定是副本的擁有組織;要先移走擁有者又卡在擁有者保護與「使用者至少一個所屬組織」,結果開錯只能停用、清不掉。
- 硬刪除:`users` 的唯一索引含已軟刪除的文件,留殭屍會讓同一組帳號永遠開不了;「同一組帳號可以重新開通」正是撤銷存在的目的。
- 租戶一旦長出子組織、成員、角色或業務資料,就不再是「開錯」,只能停用。

## Token 效期

**決策**:啟用連結 7 天、重設密碼連結 30 分鐘;單次使用、存雜湊、TTL index。效期可由環境變數調整,程式內建預設值。啟用逾期走「忘記密碼」自助,不需根組織重寄。

**理由**:啟用信常被晚看,給一週;重設密碼是當下操作,短效降低外洩風險。

## 其他規則

- 組織停用連動整棵子樹;有子孫或關聯資料者禁止刪除,只能停用。
- 搬移限租戶內,跨租戶禁止:組織上掛著使用者、角色擁有權與資料,跨租戶搬等於把它們帶到另一個租戶。
- 根組織專屬模組:「模組與權限」「資料範圍」,以及兩個權限容器「租戶作業」(`system.org-manager.tenant-ops`)與「類別作業」(`system.field-manager.category-ops`)。seed 宣告 `isRootOnly`,子孫一併視為根組織專屬。

## 取捨

- 開通整段是一個交易(ADR-0013):任一步失敗,組織、角色副本、使用者、關聯與稽核一起回復,同一組帳號可直接重新開通;啟用信排在交易成功之後,寄不出去只記 log,首任管理員走「忘記密碼」自助。撤銷開通的抹除與稽核同樣是一個交易。
- 未來按租戶差異化可用模組時,以 `org_module` 關聯表達,模板生成改讀該關聯。
