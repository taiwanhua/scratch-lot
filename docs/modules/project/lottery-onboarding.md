# 租戶開通清單(刮刮樂 + 排班與出勤)

一家新的刮刮樂公司開始用系統前要設定好的事,以及做這些事的三樣工具。漏了任何一步系統都會出狀況(例:沒有審核流程,單據送不出去)。本檔是正本:開通 skill 照它問、開通腳本照它做、示範指令灌的示範資料走同一套步驟。

| 工具       | 位置                                                                                         | 做什麼                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 開通 skill | `.claude/skills/scratch-lot-onboarding/`(`.agents/skills/` 同名)                             | 讀本檔 → 問新租戶的資料 → 寫成開通資料檔 → 請操作者在**自己的終端機**跑開通腳本(skill 不經手密碼)→ 人工步驟列成清單                        |
| 開通腳本   | `apps/db-migrator/seeds/project/onboarding/`(指令 `onboard`)                                 | 以租戶管理員登入,呼叫既有的 GraphQL 做完下表標「自動」的步驟;權限照常檢查、操作紀錄記在這位管理員名下;不連資料庫                           |
| 示範指令   | `pnpm --filter @repo/db-migrator demo …`(底座機制,見 `docs/deployment.md`「示範資料(demo)」) | 平台管理員建立標「示範」的機構與首任租戶管理員,再把 `apps/db-migrator/seeds/project/demo/` 的示範資料交給**同一支開通腳本**;三個環境都能跑 |

## 開通步驟

前提:平台管理員已在組織管理「開通租戶」建好租戶與首任租戶管理員,那位管理員已用啟用信設好密碼。

| #   | 項目                                  | 做什麼、為什麼                                                                                                                                                                             | 在哪個畫面           | 開通腳本                     |
| --- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- | ---------------------------- |
| 1   | 組織可見性                            | 租戶的可見性開關設為「包含下層」(不改底座預設值,只改這個租戶):總部人員與店長才看得到下層分店的資料                                                                                         | 組織管理             | 自動                         |
| —   | 分店                                  | 依開通資料建立分店(最上層組織的直接下層);已有同名的沿用                                                                                                                                    | 組織管理             | 自動                         |
| 2   | 使用者與總部人員的所屬                | 依開通資料建立使用者並給所屬分店與角色;**總部人員一律同時加入最上層組織**,總部若是某家分店也加入那家店。新建的人收到啟用信自己設定密碼;已存在的帳號只補缺的所屬與角色,密碼與基本資料不動   | 使用者管理           | 自動                         |
| 3   | 租戶管理員模板用 `*` 授予整層         | 專案 seed 一次做好(不是逐租戶):模板逐條列權限的話,動態權限(B9b)不會出現在租戶管理員身上                                                                                                    | 角色模板(專案 seed)  | —                            |
| 4   | 開通時建立的角色:總部管理、店長、店員 | 三個一般角色(和租戶自己建的沒有差別,畫面沒有「預設角色」標籤);權限配方見下方「角色配方」。只對新建的角色套配方:已有同名角色、而且有任何權限的不覆蓋                                        | 角色管理             | 自動                         |
| 5   | 崗位、收銀點                          | 先確認崗位選項(專案 seed:店內櫃台、店外攤位、補貨;不夠時租戶自己加),再為每家分店建立至少一個收銀點(開通資料的 `cashPoints`;已有同崗位的沿用)                                               | 欄位管理 → 檔案管理  | 自動(資料由操作者提供)       |
| 6   | 乙類與對應分店;銀行帳戶與使用組織     | 建立乙類並對應分店;建立銀行帳戶並設定使用組織                                                                                                                                              | 經銷商管理、帳戶管理 | 人工(尚未上線)               |
| 7   | 流程                                  | 依開通時建立的角色建立客製流程並綁定表單(共用流程不能用角色條件);每張表單的流程見下方「表單代號與流程」                                                                                    | 流程、表單           | 人工(尚未上線)               |
| 8   | 叫貨單的 B4 跳過組織                  | 預設「租戶」;總部是某家分店時改選那家分店                                                                                                                                                  | 流程設定             | 人工(尚未上線)               |
| 9   | 收據機(有才做)                        | 登記代理程式(配對碼)與印表機,收銀點設定印表機;給角色 `api.printing.print` / `reprint`                                                                                                      | 印表機管理           | 人工                         |
| 10  | 經銷商的兩個批購基準日                | 上線前最後一次批購的日期,匯入或手動填寫                                                                                                                                                    | 經銷商管理           | 人工                         |
| 11  | 排班                                  | 確認排班規則總部預設值、加入排班人員、建立人力需求範本                                                                                                                                     | 班表管理             | 人工(尚未上線)               |
| 12  | 通知的收件人與提醒時間                | 規格 3.4 預設收件人是「角色 店長」的四種負責人提醒(日結逾期、調貨出貨通知、證照到期、牌租繳費提醒),開通腳本建好角色後把收件人改成角色 店長;其餘類型與提醒時間照預設,需要時在通知設定頁調整 | 通知設定             | 四種收件人:自動;其餘人工確認 |

- 第 12 點的四種通知在類型宣告的預設收件人是「持有 `store.bank-deposit`」(角色 id 每個租戶不同,寫不進宣告)。開通腳本只改**還是預設值**的;租戶已調整過的不動。租戶若在通知設定頁「還原預設」,之後重跑開通腳本會再改成角色 店長(還原後就是預設值,分辨不出來)。**沒走開通腳本的租戶**,收件人停在權限預設,要自己到通知設定頁改成角色 店長。
- 每一步冪等:已經有的沿用,不改回去。某一步失敗(例:租戶管理員沒有那個權限)→ 照 api 回的錯誤停在那一步並列出未執行的步驟,已完成的保留;補好之後重跑,從缺的開始補。

## 執行開通腳本

開通資料是一個 JSON 檔(形狀見 `apps/db-migrator/seeds/project/onboarding/plan.ts`),**不放任何密碼**(出現名稱含 password 的欄位就拒絕),也不進 repo:

```json
{
  "branches": [{ "name": "中山店" }, { "name": "信義店" }],
  "headquartersBranch": null,
  "users": [
    {
      "account": "hq@example.com",
      "email": "hq@example.com",
      "name": "總部人員",
      "branches": [],
      "headquarters": true,
      "roles": ["hq"]
    },
    {
      "account": "manager@example.com",
      "email": "manager@example.com",
      "name": "中山店店長",
      "branches": ["中山店"],
      "headquarters": false,
      "roles": ["store-manager"]
    }
  ],
  "positions": [],
  "games": [
    {
      "gameCode": "5201",
      "name": "金好運",
      "unitPrice": 100,
      "ticketsPerBook": 100,
      "defaultRate": 92,
      "color": "yellow"
    }
  ],
  "cashPoints": [
    {
      "branch": "中山店",
      "positionKey": "in-store-counter",
      "name": "店內櫃台",
      "order": 1
    }
  ]
}
```

- `roles`:`hq` = 總部管理、`store-manager` = 店長、`clerk` = 店員。
- `headquartersBranch`:總部是某家分店時填那家店的名稱;總部就是租戶本身時為 `null`。
- `positions`:專案預設崗位之外的自訂崗位(`value` 英文 kebab-case、`label` 顯示名稱、選填 `color` = 標籤色票代號 `blue` / `cyan` / `green` / `lime` / `yellow` / `orange` / `red` / `pink` / `purple` / `grey`);沒有就空清單。顏色只在這個租戶自己的選項還沒有顏色時設定,租戶已選過的不動;全域選項(店內櫃台 blue、店外攤位 green、補貨 orange)的顏色由專案 seed 種下初始值、之後只有平台管理員能改,開通腳本不碰。
- `games`:開通時建立的遊戲(代號 4 碼數字、單張金額、整本張數、預設批購金額率、選填 `color`);以代號找回,已存在的不改。沒有就空清單。
- `cashPoints`:開通時建立的收銀點(`branch` 分店名稱、`positionKey` 崗位選項值 —— 專案預設的 `in-store-counter` / `outdoor-stall` / `restock` 或 `positions` 裡的、`name`、選填 `order`);以「分店 + 崗位」找回,已存在的不改;印表機不設(用分店預設)。沒有就空清單。

在**自己的終端機**執行(租戶管理員密碼在終端機輸入、不回顯;不從參數、環境變數或檔案讀):

```bash
pnpm --filter @repo/db-migrator onboard --api-url=<該環境的 api 網址> --tenant=<租戶短碼> --account=<租戶管理員帳號> --plan=<開通資料檔>
```

`--api-url` 是該環境的 api origin(`deploy/project/cloud.json` 各環境的 `apiUrl`,例 `https://api-dev.scratch-lot.com`)。`--tenant` 是要開通的租戶短碼(開通租戶時填的):登入者所屬的租戶不是它,就停在第一步,一筆都不寫。

## 角色配方

三個角色的權限每個模組一段,在 `apps/db-migrator/seeds/project/onboarding/role-grants/`(規格 3.3);租戶沒有開放的模組自動略過並列在輸出裡。目前的配方:

| 段落           | 總部管理 | 店長                        | 店員 |
| -------------- | -------- | --------------------------- | ---- |
| 總覽、申請中心 | 全部     | 全部                        | 全部 |
| 檔案管理       | 全部     | 收銀點(新增、編輯);遊戲只看 | 不給 |
| 系統管理(底座) | 不給     | 不給                        | 不給 |

系統管理(組織、使用者、角色、欄位、通知設定…)留給租戶管理員。

## 表單代號與流程

formKey 組成動態權限 `<模組>.create-<formKey>`(只有開啟 B9b 的 `store` 有),也是流程綁定用的代號;使用者畫面只看到中文名稱。審核者寫法:「店長限定 X」= 人員條件「角色 店長 且 所屬組織屬於 X(本身)」。

| 表單         | formKey             | 綁定模組                 | 開通時建立的流程                                                                                                                                    | 開通腳本 |
| ------------ | ------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 撤銷售出申請 | `sale-reversal`     | `store`                  | 一關:店長限定「分店」;B5 申請人是審核者時自動通過                                                                                                   | 尚未上線 |
| 現金更正單   | `cash-correction`   | `store`                  | 一關:店長限定「分店」;B5                                                                                                                            | 尚未上線 |
| 盤點確認申請 | `stocktake-confirm` | `store`                  | 一關:店長限定「分店」;B5                                                                                                                            | 尚未上線 |
| 結帳確認申請 | `checkout-confirm`  | `store`                  | 兩關:第 1 關 審核者 = 欄位「接班人」,類型 = 日結或接班人為空時跳過;第 2 關 店長限定「分店」,類型 = 交班且接班人不為空時跳過(用底座的跳過條件運算式) | 尚未上線 |
| 叫貨單       | `requisition`       | `purchasing.requisition` | 一關:角色 總部管理;B4 跳過組織 = 租戶(總部是分店時改選那家店)                                                                                       | 尚未上線 |
| 進貨單       | `purchase`          | `purchasing.purchase`    | 一關:店長限定「進貨分店」                                                                                                                           | 尚未上線 |
| 調貨單       | `transfer`          | `purchasing.transfer`    | 兩關:第 1 關 店長限定「出貨分店」,跳過條件 `ctx.user.orgId == 出貨分店`;第 2 關 店長限定「收貨分店」                                                | 尚未上線 |
| 補打卡申請   | `makeup-punch`      | `schedule.attendance`    | 一關:店長限定「分店」                                                                                                                               | 尚未上線 |
| 支援需求單   | `support-request`   | `schedule.manage`        | 一關:人員條件「角色 總部管理 且 所屬組織屬於租戶(最上層組織本身)」                                                                                  | 尚未上線 |

## 示範指令

`demo --mode=create`(用法、確認字串、Secret 見 `docs/deployment.md`「示範資料(demo)」)建立示範機構「示範彩券行」,再以它的首任租戶管理員跑開通腳本,開通資料來自 `apps/db-migrator/seeds/project/demo/`:

| 內容     | 示範資料                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------- |
| 分店     | 中山店、信義店(總部就是機構本身)                                                                                      |
| 使用者   | 示範總部人員(總部管理)、中山店與信義店各一位店長、一位店員;信箱 = 基底信箱 `+demo-hq` 等別名,帳號同信箱               |
| 角色     | 總部管理、店長、店員(同「角色配方」)                                                                                  |
| 自訂崗位 | 櫃台 A(cyan)、櫃台 B(purple)、彩券機旁(pink)(示範「預設崗位不夠時租戶自己加」;收銀點「彩券機旁」對應崗位「彩券機旁」) |
| 遊戲     | 5201 金好運、5164 發大財、5198 鼠來寶、5150 好運旺旺、5133 招財貓(都是販售中,顏色各不相同)                            |
| 收銀點   | 中山店:店內櫃台、店外攤位、彩券機旁(對應自訂崗位「彩券機旁」);信義店:櫃台 A、櫃台 B                                   |

- 示範帳號的密碼 = 示範密碼(只存雜湊);新建的帳號首登照一般規則要改密碼,改過的密碼重跑不改回去。首任租戶管理員不強改。
- repo 不放任何密碼或真實信箱(`seeds/project/demo/demo-data.test.ts` 會掃)。
