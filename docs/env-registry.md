# 環境變數註冊表

所有環境變數的單一清單:用途、是否機密、放哪、誰讀。**新增或異動環境變數時必須更新此表。**

判準:**憑證 / 金鑰 / 密碼 / token → Google Secret Manager(機密);設定 / 開關 / 非敏感值 → 普通環境變數。** `NEXT_PUBLIC_*` 與 `VITE_*` 會進瀏覽器,**絕不可放機密**。放哪、怎麼接線見 `docs/deployment.md`「四、環境變數管理」。

底座的 `deploy/project/cloud.json` 與 GitHub 看板整合目前皆停用;本表描述既有設定與啟用後的接線,不表示雲端 Secret、服務帳號或寄件網域已建立。

## 機密(Google Secret Manager)

Secret 名稱由專案指定;慣例是三環境各一份 `<名稱>-dev` / `<名稱>-staging` / `<名稱>`(production)。workflow 用的名稱登記在 `deploy/project/cloud.json` 各環境的 `secrets`(只記名稱,不記值),deploy.yml / reset-db.yml 由讀取器取得。建立與授權步驟見 `docs/deployment.md`「新增一個 Secret Manager 機密的標準步驟」。

## 非機密(雲端:`deploy/env/<環境>.yaml`;本地:`.env`)

api 對每個非機密變數都有內建預設值,不設也能跑;要調整就改該環境的 YAML(走 PR)。**YAML 是該環境明文變數的唯一來源**:deploy.yml 以 `--env-vars-file` 整包取代,檔內沒寫的變數部署後就不存在。所以「三環境都不寫 `MAIL_ALLOWLIST`」= 不限收件人,「staging / production 不寫 `GRAPHQL_SANDBOX`」「三環境都不寫 `WORKFLOW_MAIL_ENABLED`」= 關。
